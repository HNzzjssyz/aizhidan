01

核心指标区间自动计算

功能描述

  • 筛选核心、可监控、易出效果且无重叠因果关系的业务可控指标
  • 基于企业近期真实数据（建议近90天），通过统计算法自动计算正常运营区间
  • 区间计算采用四分位距法（IQR），对异常值具有鲁棒性
  • 当指标偏离正常区间时自动预警，推送至管理层
  • 区间随数据滚动更新，自适应业务季节性变化

算法逻辑

  • 收集指标近N天时序数据，剔除空值与明显异常
  • 计算Q1（25%分位）、Q3（75%分位）和IQR = Q3 - Q1
  • 正常区间下界 = Q1 - 1.5 × IQR
  • 正常区间上界 = Q3 + 1.5 × IQR
  • 结合业务约束裁剪（如利润率不为负）
  • 滚动窗口每日重算，平滑过渡避免跳变

核心指标选择标准与分类

指标选择标准

  • 业务相关性：直接反映企业经营健康状况，与核心目标强相关
  • 数据可得性：数据可稳定获取，采集成本低，历史数据完整
  • 灵敏度：对业务变化敏感，能及时反映异常情况
  • 可解释性：指标含义清晰，异常原因易追溯
  • 无强因果重叠：避免选取具有直接因果关系的重复指标

指标分类体系

  • 销售类：日销售额、日订单量、平均客单价、复购率
  • 库存类：库存周转率、滞销库存占比、安全库存达标率
  • 财务类：毛利率、应收账款回款周期、费用率
  • 运营类：客户下单频次、客诉率、履约准时率
行业类型 推荐核心指标 业务约束
批发零售 日销售额、订单量、客单价、库存周转率 销售额≥0、周转率>0
制造生产 日产量、良品率、设备稼动率、交货准时率 良品率∈[0,1]、稼动率∈[0,1]
服务行业 日客流量、客单价、复购率、客诉率 客诉率∈[0,1]、复购率∈[0,1]
电商行业 日GMV、转化率、客单价、退货率 转化率∈[0,1]、退货率∈[0,1]
01b

算法实现与变体方案

核心算法：IQR四分位距法

  • 将历史数据按升序排序
  • 计算Q1（第25百分位数）和Q3（第75百分位数）
  • 计算IQR = Q3 - Q1（四分位距）
  • 正常区间下界 = Q1 - 1.5 × IQR
  • 正常区间上界 = Q3 + 1.5 × IQR
  • 应用业务约束裁剪区间（如非负限制）

备选算法方案

  • MAD中位数绝对偏差法：适用于偏态分布数据，更稳健
  • 移动平均标准差法：均值±k×标准差，适用于正态分布
  • 百分位直接法：直接取[5%, 95%]分位数作为区间
  • 指数平滑法：考虑时间趋势，近期数据权重更高
import numpy as np from scipy import stats def calc_interval_iqr(data, lower_bound=None, upper_bound=None, k=1.5): """IQR四分位距法计算区间""" data_clean = data[~np.isnan(data)] q1 = np.percentile(data_clean, 25) q3 = np.percentile(data_clean, 75) iqr = q3 - q1 lower = q1 - k * iqr upper = q3 + k * iqr if lower_bound is not None: lower = max(lower, lower_bound) if upper_bound is not None: upper = min(upper, upper_bound) return {"lower": round(lower, 2), "upper": round(upper, 2), "q1": q1, "q3": q3} def calc_interval_mad(data, lower_bound=None, upper_bound=None, k=3): """MAD中位数绝对偏差法（对偏态分布更稳健）""" data_clean = data[~np.isnan(data)] median = np.median(data_clean) mad = stats.median_abs_deviation(data_clean, scale="normal") lower = median - k * mad upper = median + k * mad if lower_bound is not None: lower = max(lower, lower_bound) if upper_bound is not None: upper = min(upper, upper_bound) return {"lower": round(lower, 2), "upper": round(upper, 2), "median": median} def check_status(value, interval): """判断指标状态：正常/偏低/偏高""" if value < interval["lower"]: return "low" elif value > interval["upper"]: return "high" else: return "normal"
01c

异常等级划分与预警策略

异常等级定义

  • 正常（绿色）：值 ∈ [lower, upper]，无需关注
  • 轻度异常（黄色）：偏离区间但在2×IQR内，需观察
  • 中度异常（橙色）：偏离区间在2-3×IQR之间，需关注
  • 重度异常（红色）：偏离区间超过3×IQR，需立即处理

预警策略配置

  • 推送频率：实时/每日定时/按异常等级
  • 推送对象：按指标重要性配置不同接收人
  • 收敛规则：连续N天正常后自动解除预警
  • 静默期：同一指标异常在X小时内不重复推送
异常等级 偏离程度 响应要求 推送方式
正常 值 ∈ [lower, upper] 无需响应 不推送
轻度异常 1.5×IQR ~ 2×IQR 记录观察，24小时内确认 每日汇总推送
中度异常 2×IQR ~ 3×IQR 4小时内响应，分析原因 实时推送 + 邮件
重度异常 > 3×IQR 立即响应，1小时内介入 实时推送 + 电话通知

数据质量验证与滚动更新

数据质量检查

  • 完整性检查：有效数据量≥30天，否则提示数据不足
  • 一致性检查：与业务约束冲突的异常点标记
  • 连续性检查：时间序列断点检测
  • 单值校验：非负性、范围限制等业务规则验证

区间滚动更新策略

  • 更新频率：每日凌晨自动重算区间
  • 窗口策略：滑动窗口（最近90天）
  • 平滑过渡：新旧区间加权平滑，避免跳变
  • 季节性处理：保留同比环比数据供参考

功能描述

  • 用户通过语音或自然文本描述业务信息

03

客户库/产品库匹配校验

匹配策略

  • 精确匹配：输入与库中名称完全一致
  • 模糊匹配：基于编辑距离与关键词的相似度匹配
  • 别名匹配：支持客户/产品的常用别名映射
  • 匹配结果分级：✓ 精确 / ⚠ 模糊（需确认） / ✗ 未匹配（需手动选择）

数据来源

  • MVP阶段：支持Excel/CSV导入客户库和产品库
  • 导入字段：客户名称、联系人、地址；产品名称、编号、规格、单价
  • 匹配时优先使用编号，其次名称，最后别名
  • 未匹配项自动加入"待确认"列表，确认后可加入库中

04

数据流设计

两大核心数据流：语音制单流与指标值守流，分别覆盖"数据录入"与"数据监控"场景。

语音制单数据流

STEP 1

语音/文本输入

用户通过语音或文本描述业务信息，如"给XX公司发报价单..."

STEP 2

ASR转写

语音输入经ASR转写为文本，与直接文本输入合并进入后续流程

STEP 3

LLM结构化提取

LLM解析文本，提取单据类型、客户、产品明细、金额、付款方式等字段

STEP 4

字段校验匹配

客户名称→客户库匹配；产品名称→产品库匹配；金额自动计算校验

STEP 5

单据草稿生成

按模板填充字段，生成格式化单据草稿，低置信度字段高亮标记

STEP 6

确认/修改

用户一键确认或逐字段修改，修改后自动保存，完成录入闭环

指标值守数据流

STEP 1

数据采集

每日定时从业务系统采集核心指标数据（日销售额、订单量、毛利率等）

STEP 2

区间计算

基于近90天数据，IQR算法计算各指标正常运营区间，滚动更新

STEP 3

偏差判定

当日指标值与正常区间比对，判定正常/偏低/偏高，计算偏离程度

STEP 4

预警推送

异常指标自动推送预警通知至管理层，附偏差详情与近期趋势

⚠️

MVP阶段数据采集方式

MVP阶段不对接企业ERP/财务系统，采用手动导入Excel或API推送的方式采集业务数据。每日指标数据通过模板化Excel上传，系统自动解析入库。后续版本再逐步对接主流ERP系统。

IQR计算节点 (Code节点)

Python代码实现IQR区间计算：排序→计算Q1/Q3/IQR→确定上下界→业务约束裁剪

import numpy as np def calc_interval(data, lower_bound=None, upper_bound=None): q1 = np.percentile(data, 25) q3 = np.percentile(data, 75) iqr = q3 - q1 lower = q1 - 1.5 * iqr upper = q3 + 1.5 * iqr if lower_bound is not None: lower = max(lower, lower_bound) if upper_bound is not None: upper = min(upper, upper_bound) return {"lower": round(lower, 2), "upper": round(upper, 2)}

偏差判定节点

将当日指标值与计算得到的区间比对：值 ∈ [lower, upper] → 正常；值 < lower → 偏低；值 > upper → 偏高

风险与应对

识别MVP阶段的主要风险点，提前制定应对策略。

LLM提取准确率不达标
复杂业务描述、口语化表达、多产品混合描述可能导致字段提取错误或遗漏
中概率 高影响
多轮Prompt迭代优化；增加示例few-shot；低置信度字段强制确认；用户反馈闭环持续优化
客户/产品模糊匹配误判
相似名称客户或产品可能被错误匹配，导致单据关联错误
中概率 中影响
模糊匹配结果必须用户确认；匹配置信度分级展示；优先精确匹配；支持用户手动选择
语音识别准确率不足
行业术语、方言口音、噪声环境可能导致ASR转写错误
低概率 中影响
ASR转写结果展示给用户确认；支持文本直接输入作为备选；行业术语自定义词库
Coze平台能力限制
Coze Workflow节点限制、Knowledge Base容量限制、API调用频率限制等
低概率 中影响
提前验证Coze平台关键限制；复杂计算通过外部API扩展；必要时部分功能自建后端
IQR算法对非正态分布数据不适用
部分业务指标可能呈偏态分布，IQR区间可能不够准确
低概率 低影响
MVP阶段IQR足够使用；预留算法升级接口；后续可引入MAD（中位数绝对偏差）或业务规则修正

成功验收标准

MVP Demo需满足以下核心验收标准，方可认为验证成功。

🎯

制单准确率 ≥ 80%

对标准业务描述的语音/文本输入，AI生成单据的字段准确率不低于80%，核心字段（客户、产品、金额）准确率不低于90%

⚡

端到端制单 ≤ 30秒

从用户完成语音/文本输入到生成单据草稿，端到端响应时间不超过30秒（不含用户确认时间）

✅

确认修改闭环 ≤ 3步

用户从看到单据草稿到完成确认/修改，操作步数不超过3步（查看→修改→确认）

📊

指标区间自动计算可用

给定90天历史数据，系统能自动计算3-5个核心指标的正常区间，异常数据能触发预警推送

🔗

客户/产品库匹配可用

导入客户库/产品库后，单据生成时能自动匹配核心字段，精确匹配率≥85%，模糊匹配需用户确认

📋

3类单据全流程可演示

销售订单、报价单、出库单三类单据的语音/文本输入→解析→校验→生成→确认全流程可完整演示
