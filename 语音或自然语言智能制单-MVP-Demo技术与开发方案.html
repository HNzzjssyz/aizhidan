01

问题定义与核心价值

中小企业一线员工普遍抵触手动填报结构化数据和制作格式化单据——这是数据值守体系落地的第一道门槛。本专项方案聚焦解决"数据怎么快速录进来"这个最紧迫问题。

🎙️

语音/自然语言录入

用户只需"说"或"打字"描述业务信息，无需手动填写表格字段，AI自动完成结构化提取，将非结构化输入转化为结构化单据

✏️

八成匹配 + 小调整

AI生成80%准确率的单据草稿，用户只需对少量字段做微调即可达到100%精确，大幅降低录入工作量与心理门槛

✓

核心字段精准校验

客户名称、产品编号等必须精准的字段，通过企业已有客户库/产品库自动匹配校验，确保关键数据不出错

💡

核心设计哲学

不追求AI一步到位，接受80%-95%的生成准确率，通过极简的确认修改交互补齐剩余5%-20%。核心逻辑是：AI干粗活，人做精修——让AI承担80%的重复性结构化工作，让人只做20%的关键判断与修正，形成"快速录入→八成匹配→小调整→精确保存"的完整闭环。

02

核心流程总览

从用户输入到精确保存，完整闭环分为六步，每一步职责清晰、可独立优化。

STEP 1

语音/文本输入

用户通过语音录制或文本输入描述业务信息

STEP 2

ASR转写 + 预处理

语音转文本，清洗无效字符，标准化数字与关键词

STEP 3

LLM结构化提取

AI解析文本，按单据Schema提取所有字段，输出JSON

STEP 4

字段校验匹配

客户→客户库匹配；产品→产品库匹配；金额自动计算

STEP 5

单据草稿展示

按模板渲染格式化单据，高亮低置信度与待确认字段

STEP 6

交互修正 → 保存

用户一键确认或逐字段修改，修改后保存完成闭环

🔄

闭环关键：Step 5→6 是核心体验

AI生成草稿只是起点，真正决定用户体验的是"看到草稿后如何快速修正并保存"。本方案将80%的交互设计精力投入在Step 5-6，确保修正操作极简、直觉、零学习成本。

输入预处理规则

文本清洗

  • 去除多余空格、标点符号标准化
  • 口语化数字转标准格式："八十五块"→85.00
  • 单位标准化："箱"→箱、"个"→个、"件"→件
  • 识别单据类型关键词："报价单""订单""出库"等

ASR纠错策略

  • 行业术语纠错：基于产品库/客户库的发音相似度修正
  • 数字纠错：ASR常见数字识别错误自动修正
  • 转写结果展示给用户确认，支持手动修改转写文本
  • 保留原始音频，必要时可回听
04

解析层：AI结构化提取

核心AI能力层——将非结构化的自然语言文本转化为结构化的单据JSON数据。这是"八成匹配"的关键引擎。

01

LLM结构化提取

提取策略

  • 按单据模板Schema定义字段清单
  • LLM按Schema逐字段提取，输出结构化JSON
  • 无法确定的字段填null，不猜测
  • 每个字段附带置信度评分（0-1）
  • 置信度低于0.7的字段标记为"待确认"

多轮引导补全

  • 必填字段缺失时，Bot主动追问
  • 追问采用自然对话方式，非表单式
  • 最多追问2轮，避免用户烦躁
  • 2轮后仍缺失的必填字段标红提示
  • 非必填字段缺失时静默跳过
你是一个单据信息提取助手。请从用户输入中提取以下信息，按JSON格式输出： { "doc_type": "销售订单|报价单|出库单", "customer_name": "提取的客户名称", "products": [ { "name": "产品名称", "spec": "规格", "qty": 数量, "unit": "单位", "price": 单价 } ], "payment_term": "付款条件", "tax_included": true|false, "remark": "备注信息", "confidence": { "customer_name": 0.0-1.0, "products": [0.0-1.0], "payment_term": 0.0-1.0 } } 对无法确定的字段填null。用户输入：{{input}}

05

校验层：客户库/产品库匹配

核心字段必须精准——客户名称和产品信息通过企业已有数据库进行匹配校验，这是"八成匹配"提升到"可用"的关键一步。

01

三级匹配策略

匹配流程

  • 第一级：精确匹配——输入与库中名称完全一致
  • 第二级：模糊匹配——编辑距离+关键词相似度
  • 第三级：别名匹配——客户/产品的常用别名映射
  • 匹配结果分级：✓ 精确 / ⚠ 模糊（需确认） / ✗ 未匹配
  • 匹配时优先编号，其次名称，最后别名

校验规则

  • 客户名称：必须匹配到库中唯一客户，否则需用户手动选择
  • 产品名称：必须匹配到库中唯一产品，否则需用户手动选择
  • 单价校验：与产品库参考单价对比，偏差>20%标黄提示
  • 金额自动计算：数量×单价=行金额，各行求和=合计
  • 计算结果与LLM提取金额交叉校验，不一致时以计算为准
✓ 精确匹配
输入："深圳华创科技"
→ 深圳华创科技有限公司 (CUST-001)
⚠ 模糊匹配
输入："华创"
→ 候选：深圳华创科技 / 广州华创电子，请确认
✓ 别名匹配
输入："A3复印纸"
→ A3打印纸 (PROD-A3-001) [别名: A3复印纸]
✗ 未匹配
输入："新客户某某公司"
→ 未找到匹配，请手动选择或新建客户

06

展示层：单据草稿渲染

AI生成草稿后如何展示给用户，直接影响修正效率。核心原则：一眼看清哪些字段需要关注，哪些可以直接确认。

01

字段状态分级展示

三种字段状态

  • ✓ 已确认（绿色）——精确匹配或高置信度，可直接通过
  • ⚠ 待确认（黄色）——模糊匹配或中置信度，需用户确认
  • ✗ 需补充（红色）——未匹配或低置信度，必须用户处理

视觉设计

  • 已确认字段：正常显示，无特殊标记
  • 待确认字段：黄色高亮背景 + "⚠" 标记
  • 需补充字段：红色边框 + "✗" 标记 + 占位提示
  • 页面顶部汇总：X个待确认 / Y个需补充
  • 全部确认后，汇总条变绿，一键保存按钮高亮

07

修正层：交互式确认修改

这是"八成匹配→百分精确"的关键环节。设计目标：修正操作≤3步，零学习成本，直觉式交互。

01

两种修正模式

⚡

一键确认模式

所有字段状态为"✓已确认"时，用户直接点击"确认保存"按钮，一步完成。适用于AI生成准确、无需修改的场景。

1步完成 最佳体验
✏️

逐字段修正模式

点击任意字段进入编辑状态：文本字段直接修改；匹配字段弹出候选列表选择；下拉字段弹出选项。修改完点击其他区域自动保存。

≤3步 精准修正
02

修正交互详细设计

1

点击待修改字段

点击单据中任意字段（黄色⚠或红色✗优先），进入编辑状态。已确认字段也可点击修改。

2

选择修改方式

文本字段（日期、备注等）：直接编辑文本
匹配字段（客户、产品）：弹出候选列表，支持搜索筛选
数值字段（数量、单价）：数字输入框，自动计算金额
下拉字段（付款方式、含税等）：弹出预设选项

3

自动保存 + 状态更新

修改完成后点击其他区域或按回车，自动保存修改。字段状态实时更新：修正后变为✓已确认。全部字段确认后，"确认保存"按钮高亮可点击。

03

智能辅助修正

候选列表智能排序

  • 匹配字段弹出候选列表时，按相关度排序
  • 最近使用过的客户/产品优先展示
  • 支持输入关键词实时搜索筛选
  • 列表最多展示5个候选，避免信息过载

联动自动计算

  • 修改数量或单价→自动重算行金额与合计
  • 选择产品→自动填充规格、参考单价
  • 选择客户→自动填充联系人、地址
  • 修改任一字段→相关联字段自动更新
🎯

交互设计核心原则

零学习成本：点击即编辑，无需培训。最少操作：确认≤1步，修正≤3步。即时反馈：每次修改立即看到结果，状态实时更新。容错：任何修改都可撤销，保存前可反复调整。

制单 Bot 设计

🤖

制单 Bot 职责

接收用户语音/文本输入，调用单据解析Workflow，返回结构化单据草稿。内置Prompt引导用户补充缺失信息，管理多轮对话上下文。识别用户意图（新建单据/修改已有单据），路由到对应Workflow。

对话式交互 多轮引导 意图识别

单据解析 Workflow 详细设计

1

输入预处理节点

接收用户原始文本，清洗无效字符，标准化数字格式（如"85块"→85.00），识别单据类型关键词

2

LLM结构化提取节点

调用LLM，按单据模板Schema提取字段，输出JSON结构（含置信度评分）

3

客户库匹配节点

将提取的客户名称与Knowledge Base中客户库进行匹配：精确匹配→模糊匹配→返回候选列表

4

产品库匹配节点

逐条匹配产品名称与产品库，补充产品编号、规格等缺失字段，校验单价合理性

5

金额计算与校验节点

根据匹配后的产品明细自动计算行金额与合计金额，与LLM提取的金额交叉校验

6

单据生成与状态标记节点

按对应单据模板填充所有字段，根据置信度和匹配结果标记字段状态（✓/⚠/✗），输出格式化单据草稿

MVP功能范围

聚焦"语音/自然语言→单据创建→交互修正→保存"这一条核心链路，避免范围蔓延。

✓ MVP 包含

  • 语音录制输入 + ASR转写
  • 自然语言文本输入
  • AI结构化提取（含置信度评分）
  • 多轮对话引导补全缺失字段

  • 多企业/多租户支持

风险与应对

识别智能制单MVP的主要风险点，提前制定应对策略。

LLM提取准确率不达标
复杂业务描述、口语化表达、多产品混合描述可能导致字段提取错误或遗漏
中概率高影响
多轮Prompt迭代优化；增加few-shot示例；低置信度字段强制确认；用户反馈闭环持续优化
客户/产品模糊匹配误判
相似名称客户或产品可能被错误匹配，导致单据关联错误
中概率中影响
模糊匹配结果必须用户确认；匹配置信度分级展示；优先精确匹配；支持手动选择
语音识别准确率不足
行业术语、方言口音、噪声环境可能导致ASR转写错误
低概率中影响
ASR转写结果展示给用户确认；支持文本直接输入备选；行业术语自定义词库
Coze平台交互能力限制
Coze对话界面可能无法实现理想的单据编辑交互（如点击字段修改、候选列表等）
中概率中影响
MVP先用Coze对话式交互（Bot引导逐字段确认）；必要时开发轻量H5前端实现富交互

验收标准

MVP Demo需满足以下核心验收标准，方可认为智能制单功能验证成功。

🎯

制单准确率 ≥ 80%

对标准业务描述的语音/文本输入，AI生成单据的字段准确率不低于80%，核心字段（客户、产品、金额）准确率不低于90%

⚡

端到端制单 ≤ 30秒

从用户完成语音/文本输入到生成单据草稿，端到端响应时间不超过30秒（不含用户确认时间）

✅

修正闭环 ≤ 3步

用户从看到单据草稿到完成确认/修改保存，操作步数不超过3步（查看→修改→确认）

🔗

客户/产品库匹配可用

导入客户库/产品库后，单据生成时能自动匹配核心字段，精确匹配率≥85%，模糊匹配需用户确认

📋

3类单据全流程可演示

销售订单、报价单、出库单三类单据的语音/文本输入→解析→校验→展示→修正→保存全流程可完整演示

🔄

修正后100%精确保存

经用户确认/修改后保存的单据，所有字段数据100%准确，无残留错误

🚀

MVP之后的演进方向

MVP验证成功后，可按以下方向迭代：
v0.2：更多单据类型、单据审批流程、打印导出PDF
v0.3：ERP系统对接、历史单据管理、自定义模板
v1.0：多租户SaaS化、移动端原生App、高级分析报表
