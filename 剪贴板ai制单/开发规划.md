# AI制单 — 剪贴板智能制单开发规划

## 整体流程

用户通过 Coze 智能体对话 → AI 生成 JSON 订单数据 → 复制到剪贴板 → 前端自动捕获 → 匹配客户和产品 → 用户确认 → 提交订单

---

## 环节一：后端匹配查询（暂不开发）

### 目标
将本地 mockData 模拟匹配逻辑替换为后端数据库查询，通过拼音索引实现客户和产品的精确/模糊匹配。

### 具体内容
1. **客户匹配接口**
   - 输入：客户名称（中文）
   - 后端逻辑：将客户名称转为拼音，与数据库中客户名称拼音表做匹配
   - 输出：匹配的客户列表（含客户ID、名称、地址、联系人、匹配度）

2. **产品匹配接口**
   - 输入：产品名称（中文），可选规格信息
   - 后端逻辑：将产品名称转为拼音，与数据库中产品名称拼音表做匹配
   - 输出：匹配的产品列表（含产品ID、编号、名称、SKU、规格、匹配度）

3. **数据结构调整**
   - 前端移除 mockData 本地数据依赖
   - 定义标准 API 响应格式
   - 添加接口调用错误处理和降级逻辑

### 依赖
- 后端数据库中需建立客户名称拼音索引表和产品名称拼音索引表
- 需提供客户查询和产品查询的 REST API

---

## 环节二：前端结果展示融合（当前开发）

### 目标
完善前端界面，将剪贴板捕获的原始数据与匹配查询结果融合展示，让用户清晰看到数据来源和匹配状态。

### 具体内容
1. **匹配结果展示优化**
   - 客户匹配结果：显示原始识别名称 → 匹配到的客户名称，标注匹配类型（精确/模糊/未匹配）
   - 产品匹配结果：每个产品显示原始名称 → 匹配到的产品，标注匹配类型（SKU精确/品名模糊/未匹配）
   - 匹配进度动画：从"匹配中"到"匹配完成"的过渡

2. **数据来源标识**
   - 区分显示"剪贴板原始数据"和"匹配结果数据"
   - 未匹配项高亮提示，引导用户手动选择或新建

3. **交互流程完善**
   - 多候选客户/产品的选择弹窗
   - 未匹配产品的重新匹配和新建流程
   - 批量确认和状态切换

4. **前端数据结构标准化**
   - 定义统一的订单数据结构，为后续环节1（后端接口）和环节4（订单提交）做准备
   - 剪贴板 JSON → 标准化订单对象 → 前端展示 的数据流清晰化

### 当前状态
- 基础匹配展示已有，使用本地 mockData
- 需优化数据融合展示和交互细节

## 环节三：可编辑功能补充（暂不开发）

### 目标
为产品明细添加单价、金额和备注的可编辑功能，允许用户手动修正 AI 识别不准确的内容。

### 具体内容
1. **单价编辑**
   - 点击单价字段进入编辑模式
   - 支持手动输入或从产品库选择参考价
   - 编辑后自动重新计算小计和订单总额

2. **金额计算**
   - 小计 = 数量 × 单价，自动计算
   - 订单总额 = 所有产品小计之和，实时更新
   - 支持手动覆盖自动计算结果

3. **备注编辑**
   - 点击备注字段进入编辑模式
   - 支持 AI 识别的备注和手动补充的备注合并显示

4. **编辑状态管理**
   - 已编辑字段标注"已修改"标识
   - 支持撤销修改，恢复原始识别值
   - 编辑后自动将产品状态改为"待确认"

---

## 环节四：订单提交保存（待开发）

### 目标
用户确认客户和产品信息后，调用后端接口将完整订单数据写入业务系统数据库。

### 具体内容
1. **提交前校验**
   - 必填项检查：客户ID、至少一个产品、产品数量和单价
   - 状态检查：所有产品必须为"已确认"状态
   - 数据完整性检查

2. **订单数据组装**
   - 按后端接口要求的格式组装订单数据
   - 包含：客户ID、产品列表（产品ID、数量、单价、金额、备注）、订单总额、备注等

3. **接口调用**
   - 调用后端订单创建接口
   - 处理成功/失败响应
   - 成功后显示订单号，提供"完成并重置"操作

4. **提交后处理**
   - 成功：显示订单成功弹窗，展示订单号和关键信息
   - 失败：显示错误信息，允许修改后重新提交
   - 提供订单详情查看入口

### 依赖
- 后端需提供订单创建 REST API
- 需定义订单数据提交格式规范
