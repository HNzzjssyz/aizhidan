方案总览

固定左右布局，右侧复用 Coze Chat SDK，左侧为制单业务区，通过剪贴板监听实现跨区通信。

📋

固定左右布局

左侧：制单业务区（客户信息、产品明细、匹配结果、操作按钮）。右侧：Coze 智能体对话区（Chat SDK iframe）。

左：业务 右：对话
🔗

剪贴板跨区通信

Coze SDK 以 iframe 嵌入，主页面无法直接访问 iframe 内部 DOM。通过监听剪贴板实现零侵入通信：用户复制 JSON → 主页面捕获 → 自动填充。

零侵入 跨 iframe
🤖

Coze Chat SDK

直接复用 Coze 封装好的 Chat SDK，无需自行开发对话界面。智能体返回结构化 JSON，用户一键复制触发左侧填充。

官方 SDK 零开发
🎯

核心设计原则

最小改动：复用 Coze Chat SDK，不修改智能体逻辑。用户主动触发：复制操作由用户主动发起，不涉及自动抓取 iframe 内容。格式约定：智能体 Prompt 约定输出 JSON 格式，前端通过正则提取。

03

剪贴板监听机制

三层监听策略，确保在不同浏览器和场景下都能可靠捕获剪贴板内容。

01

三层监听策略

Layer 1：copy 事件

  • 监听 document 的 copy 事件
  • 通过 window.getSelection() 获取选中文本
  • 适用于：页面内任何区域的复制操作
  • 局限：无法捕获 iframe 内的复制（跨域限制）

Layer 2：paste 事件

  • 监听 document 的 paste 事件
  • 通过 clipboardData.getData('text') 获取粘贴内容
  • 适用于：用户在左侧区域粘贴内容
  • 局限：需要用户主动粘贴到左侧区域

Layer 3：clipboard.readText 轮询

  • 每秒调用 navigator.clipboard.readText() 读取剪贴板
  • 与上次内容比对，检测变化
  • 适用于：捕获所有来源的复制（包括 iframe 内）
  • 前提：需要 Secure Context（localhost 或 HTTPS）
  • 权限：首次需用户授权剪贴板读取权限

三层策略互补关系

  • copy 事件：即时响应，零延迟
  • paste 事件：用户主动粘贴时触发
  • readText 轮询：兜底方案，捕获 iframe 内复制
  • 三层叠加，覆盖所有复制场景
  • 去重机制：记录上次内容，避免重复处理
02

JSON 提取算法

从剪贴板文本中提取制单 JSON，支持多种格式包裹。

// 按优先级尝试多种提取模式 const patterns = [ /```json\s*([\s\S]*?)```/, // Markdown 代码块包裹 /```\s*([\s\S]*?)```/, // 无语言标记代码块 /(\{[\s\S]*"doc_type"[\s\S]*\})/, // 含 doc_type 字段的 JSON /(\{[\s\S]*"customer_name"[\s\S]*\})/,// 含 customer_name 字段 /(\{[\s\S]*"products"[\s\S]*\})/ // 含 products 字段 ]; for (const pattern of patterns) { const match = text.match(pattern); if (match && match[1]) { try { const obj = JSON.parse(match[1].trim()); if (obj.doc_type || obj.customer_name || obj.products) return obj; // 命中制单 JSON } catch (e) { continue; } } }
⚠️

Secure Context 要求

Layer 3 的 navigator.clipboard.readText() 需要 Secure Context：localhost 或 HTTPS。直接打开本地 HTML 文件（file:// 协议）不支持此 API。开发时务必通过 python3 -m http.server 8080 启动本地服务器访问。

JSON 通信协议

Coze 智能体与前端页面之间的 JSON 格式约定，是剪贴板通信的核心契约。

01

智能体输出 JSON Schema

智能体 Prompt 约定输出以下 JSON 结构，前端按此 Schema 解析填充。

{ "doc_type": "销售订单 | 报价单 | 出库单", // 单据类型（必填） "customer_name": "深圳华创科技有限公司", // 客户名称（必填） "customer_pinyin": "shen_zhen_hua_chuang_ke_ji_you_xian_gong_si", // 客户拼音（必填，用于后台查询） "payment_term": "月结30天", // 付款方式（可选） "remark": "本周五前发货", // 备注（可选） "products": [ // 产品明细（必填 ≥1） { "name": "A3打印纸", // 产品名称（必填） "pinyin": "A3_da_yin_zhi", // 产品拼音（必填，用于后台查询） "spec": "70g 500张/包", // 规格型号（可选） "spec_pinyin": "70g_500zhang_bao", // 规格拼音（可选） "qty": 100, // 数量（必填） "unit": "箱", // 单位（可选） "price": 280 // 单价（可选） } ] }
02

智能体 Prompt 约定

输出格式要求

  • 必须输出合法 JSON，用 ```json 代码块包裹
  • doc_type、customer_name、products 为必填字段
  • 无法确定的字段填 null，不猜测
  • 金额自动计算：qty × price = 行金额
  • JSON 后附带简短自然语言确认

前端解析容错

  • 支持 ```json 包裹和裸 JSON 两种格式
  • 只校验 doc_type / customer_name / products 三字段
  • products 至少含 name 和 qty
  • 缺失的可选字段使用默认值
  • 解析失败时提示用户重新复制

实现要点

将方案落地到现有项目代码中的关键实现细节。

01

Coze Chat SDK 嵌入

SDK 加载

  • 在 <head> 中加载 Coze Chat SDK 脚本
  • CDN：lf-cdn.coze.cn（国内节点）
  • 版本：1.2.0-beta.8（当前最新）
  • 需配置 botId 和 PAT Token

初始化代码

  • new CozeWebSDK.WebChatClient() 创建实例
  • config.botId：智能体 ID
  • auth.type: 'token'，auth.token: PAT
  • ui.base.lang: 'zh-CN'
  • ui.asstBtn.isNeed: false（隐藏浮动按钮）
// Coze Chat SDK 初始化 const cozeWebSDK = new CozeWebSDK.WebChatClient({ config: { botId: 'YOUR_BOT_ID', isIframe: false, }, auth: { type: 'token', token: 'YOUR_PAT_TOKEN', onRefreshToken: async () => 'YOUR_PAT_TOKEN', }, ui: { base: { lang: 'zh-CN' }, asstBtn: { isNeed: false }, } });

剪贴板监听核心代码

// Layer 1: copy 事件 — 即时响应 document.addEventListener('copy', function(e) { const selection = window.getSelection().toString(); if (selection) { setTimeout(() => handleClipboardText(selection), 100); } }); // Layer 2: paste 事件 — 用户主动粘贴 document.addEventListener('paste', function(e) { const text = e.clipboardData.getData('text'); if (text) { setTimeout(() => handleClipboardText(text), 100); } }); // Layer 3: clipboard.readText 轮询 — 兜底方案 let lastClipboardContent = ''; setInterval(function() { if (navigator.clipboard && navigator.clipboard.readText) { navigator.clipboard.readText().then(function(text) { if (text && text !== lastClipboardContent && text.length > 10) { lastClipboardContent = text; handleClipboardText(text); } }).catch(() => {}); } }, 1000);
03

与现有方案D代码的整合

替换内容

  • 删除方案D中的模拟对话区 HTML 和 JS
  • 删除 sendChatMessage / addChatBubble 等模拟函数
  • 删除 mockData 及相关模拟逻辑
  • 右侧替换为 Coze Chat SDK iframe

保留内容

  • 左侧制单业务区完整保留（客户卡片、产品列表、匹配弹窗）
  • showMatchProgress / fillOrderDraft 逻辑保留
  • 客户候选弹窗、产品候选弹窗保留
  • 语音录音 + Coze 语音转文字 API 保留
🔗

整合后的数据流变化

方案D原流程：模拟对话 → sendChatMessage → mockData 匹配 → showMatchProgress → fillOrderDraft
剪贴板方案流程：Coze SDK 对话 → 用户复制 JSON → 剪贴板监听 → extractJSON → fillOrderDraft

核心变化：数据入口从模拟函数变为剪贴板监听，左侧填充逻辑（fillOrderDraft）完全不变。

开发任务清单

Step 1：Coze SDK 嵌入

  • 在 coze.cn 创建/配置智能体
  • 配置 Prompt 约定 JSON 输出格式
  • 发布 Chat SDK 渠道
  • 获取 botId，生成 PAT Token
  • 在页面中加载 SDK 并初始化

Step 2：剪贴板监听集成

  • 实现三层监听（copy / paste / readText）
  • 实现 JSON 提取算法（多模式正则匹配）
  • 实现 Schema 校验和字段映射
  • 对接 fillOrderDraft 填充逻辑
  • 添加监听状态指示和日志

Step 3：匹配查询对接

  • 填充完成后自动提交后台匹配
  • 客户库拼音匹配查询
  • 产品库分层匹配查询
  • 匹配结果回填到左侧业务区

Step 4：端到端验证

  • Coze 对话 → JSON 输出验证
  • 复制 → 监听 → 填充全流程验证
  • 多产品场景验证
  • 异常场景验证（格式错误、字段缺失）
