01

项目定义与愿景

项目定义

智能创建引擎是一套通用的业务数据智能创建框架，通过自然语言处理和智能体技术，将传统手动录入表单的方式升级为"对话即创建"的智能交互模式。用户只需用自然语言描述业务需求，系统即可自动识别关键实体、匹配已有数据、填充表单草稿，最终完成业务数据的快速创建。

解决的核心问题
  • 手动录入繁琐：传统表单需要逐字段填写，客户名、产品名等需要从下拉列表中查找选择
  • AI过度发散：通用大模型对话随意性大，输出格式不统一，难以与企业业务系统对接
  • 规则适配难：不同企业有不同的分类体系、价格策略、业务规则，通用方案难以满足
  • 信息收集成本高：创建客户档案需要收集大量信息，人工沟通成本高
🎯 项目愿景

搭建一套可扩展的通用智能业务创建框架，通过标准化JSON协议实现框架与智能体解耦，将传统手动录入工作交由智能体完成，让销售人员从繁琐行政事务中解放，聚焦核心业务。

02

核心价值主张

智能创建引擎为企业和用户带来三大核心价值：

框架与智能体解耦

通过标准化JSON协议，实现前端框架与后端智能体的完全解耦，可灵活扩展智能体的各类能力

效率大幅提升

将繁琐的手动录入、信息收集工作交由智能体完成，用户操作从分钟级降至秒级

企业级适配

支持按租户加载分类字典、价格策略、业务规则，适配不同企业的个性化需求

传统方式

手动选择客户 → 手动搜索产品 → 逐行录入数量规格 → 核对价格 → 确认提交，平均耗时 3-5 分钟/单

智能创建

语音/文本输入需求 → 智能体自动识别 → 拼音匹配填充 → 一键确认提交，平均耗时 10-15 秒/单

03

设计优势

1
渐进式集成已有研究成果

无需从零开始，可复用已有的智能体研究成果，通过标准协议逐步接入框架，降低开发风险

2
专属智能体独立优化

每个业务场景对应独立智能体，可独立打磨Prompt和知识库，精准度互不干扰，避免单一智能体的复杂度膨胀

3
三级拼音字头匹配

支持产品品名、型号、SKU、技术参数的拼音索引，支持不同输入排序习惯，显著提升识别命中率

4
外部数据源自动补全

创建客户时识别企业名称后，可调用智能体集成天眼查等外部API，自动拉取工商信息完成档案补全

5
多模态输入支持

支持语音输入、文本输入、图片/文件上传、剪贴板粘贴等多种输入方式，适应不同使用场景

04

模块分类说明

项目按业务场景分为两大模块类型，采用统一的智能体协议但表单结构有所不同：

模块类型 覆盖场景 表单结构 核心识别逻辑
制单模块 销售订单、采购订单、报价单 表头主体 + 子产品明细 客户/供应商名称 + 产品信息（品名/型号/规格整合）
单表模块 客户建档、销售商机、项目创建 扁平字段表单 自然语言提取后拆分填充到各字段
制单模块特征

包含主实体（客户/供应商）+ 明细行（产品/物料），字段结构化程度高，匹配逻辑以实体检索为主，输出为多行明细表格

单表模块特征

单一对象，字段以属性为主（名称、联系方式、地址、分类等），匹配逻辑以查重+补全为主，输出为扁平字段表单

智能体与框架之间通过标准JSON协议通信，实现完全解耦。框架仅关心输出格式，不关心智能体内部实现。

// 智能体输出结构（所有智能体必须遵循） { "agent_type": "order", // agent | quote | purchase | customer | opportunity "session_id": "uuid-xxx", // 会话ID，用于关联上下文 "confidence": 0.95, // 整体置信度 0-1 "raw_text": "深圳华创要A3打印纸100箱", // 原始输入 "entities": [ // 识别出的实体列表 { "role": "subject", // subject | detail | meta "type": "customer", // customer | supplier | product | material | ... 1
用户输入

用户通过语音或文本输入业务需求，如"深圳华创要A3打印纸100箱"

2
智能体识别

专属智能体解析输入，提取实体（客户名、产品名、数量），输出标准JSON

3
拼音匹配

框架层调用拼音匹配引擎，将识别结果与系统已有数据匹配，返回候选列表

4
表单填充

用户确认匹配结果后，自动填充表单草稿，可逐字段修改

5
提交创建

用户确认无误后，调用业务API完成数据创建

07

智能体扩展方案

新增一个业务场景只需4步配置，无需改动框架核心代码。整个流程以配置为主，开发为辅。

1
创建专属智能体

在扣子平台创建新智能体，编写Prompt定义实体提取规则，配置知识库，发布获取botId

2
定义表单模板

在框架中注册新场景的表单模板（JSON Schema），定义字段、布局、校验规则

3
实现业务适配器

实现 BusinessAdapter 接口，包括实体匹配、数据校验、提交创建三个方法

4
注册到路由器

在智能体路由器中注册新场景配置（名称、图标、颜色、botId、适配器）

注册配置示例
// 在 agentConfig 中新增一项即可扩展新场景 const agentConfig = { // ... 已有智能体 newScenario: { name: '智能XXX', // 左侧导航显示名称 desc: '场景描述', // 副标题 chatName: 'XXX智能体', // 对话区智能体名称 icon: 'ri-xxx-line', // Remix Icon 名称 color: 'blue', // 主题色 botId: '73428668****', // 扣子平台botId quickActions: ['示例输入1', '示例输入2'], // 快捷操作 formTemplate: () => '表单HTML模板', // 表单渲染函数 adapter: new NewScenarioAdapter() // 业务适配器实例 } }
