⚠️

关键洞察：ASR准确率是整个制单链路的瓶颈

语音制单的数据流为 ASR → LLM提取 → 字段校验 → 单据生成。ASR是第一环，如果"深圳华创科技"被识别为"深圳华创科捷"，下游LLM和字段校验都无法自动修复。因此，支持自定义热词是选型的决定性因素。

SaaS多租户适配性说明（2026-05-12补充）：阿里云ASR热词功能存在配额限制（单表500个热词、最多10张表共5000个），在通用SaaS场景下无法承载数千上万家企业的差异化热词需求。因此，热词方案暂不适用于通用SaaS系统，通用场景采用拼音索引方案在后端匹配环节兜底。热词方案保留为大客户个性化优化的可选项。

02

五大技术路线详解

从浏览器原生API到云端ASR、从本地WASM推理到开源模型自建，逐一分析各路线的优劣与适用性。

01
Web Speech API
浏览器原生语音识别接口
MVP可用

技术特征

  • 浏览器内置 API，零依赖，几行代码即可接入
  • Chrome/Edge 底层调用 Google 云 ASR，中文质量好
  • 支持实时流式输出，延迟 < 500ms
  • 完全免费，无调用量限制
  • 支持 continuous 和 interimResults 模式
const recognition = new ( window.SpeechRecognition || window.webkitSpeechRecognition )(); recognition.lang = 'zh-CN'; recognition.continuous = true; recognition.interimResults = true; recognition.start();

优劣分析

  • 零成本、零集成难度
  • 实时流式输出，用户体验好
  • 国内访问 Google 服务不稳定，可能被墙
  • 仅 Chrome/Edge 有效，Safari/Firefox 支持差
  • 无法自定义行业术语热词
  • 无法控制 ASR 引擎，依赖浏览器实现
  • Safari 使用本地模型，中文质量极差

02
国内云 ASR 服务
阿里云 / 讯飞 / 腾讯云 / 百度 — WebSocket 实时识别
⭐ 首选推荐

接入架构

  • 前端通过 MediaRecorder 采集麦克风音频
  • WebSocket 实时推流至云 ASR 服务
  • 流式返回识别文本，前端实时展示
  • 识别完成后文本传入 LLM 进行结构化提取
// 浏览器录音 → WebSocket → 云ASR navigator.mediaDevices.getUserMedia({ audio: true }) .then(stream => { const ws = new WebSocket( 'wss://nls-gateway-cn-shanghai.aliyuncs.com/...' ); // 实时推送音频帧，流式接收识别结果 });

四大厂商对比

  • 阿里云：1.80~3.50元/h，支持热词，Paraformer仅0.288元/h，有浏览器端JS SDK
  • 讯飞：~2元/h，中文老牌强项，方言支持好，有前端SDK
  • 腾讯云：~2元/h，每月5h免费，与微信生态协同
  • 百度：~1.5元/h，价格最低，有免费额度
  • 共同优势：国内节点延迟 < 300ms，中文质量顶级
  • 需后端中转或前端直连 WebSocket
  • 有调用量成本（但MVP阶段极低）
03
Coze 内置语音插件
字节跳动 Coze 平台内置 ASR 能力
MVP首选

技术特征

  • Coze 平台内置语音输入能力，零代码接入
  • 底层使用字节豆包 ASR，中文质量好
  • 包含在 Coze 平台费用内，无额外成本
  • 直接在 Coze 对话界面中使用
  • 与制单 Bot、Workflow 无缝衔接

优劣分析

  • 零开发成本，开箱即用
  • 与 Coze Bot/Workflow 深度集成
  • 中文识别质量可靠
  • 黑盒，无法自定义行业术语热词
  • 无法优化 ASR 环节的质量
  • 延迟受 Coze 整体链路影响
  • 自建前端 H5 时需替换方案

04
浏览器端 WASM 本地推理
Sherpa-ONNX Web / Whisper-Web (transformers.js)
关注

Sherpa-ONNX Web

  • 支持编译为 WebAssembly，浏览器本地运行
  • 模型在浏览器中加载，麦克风音频本地推理
  • 完全离线，零 API 成本，无隐私问题
  • 支持中文模型（Paraformer 等）
  • 首次加载慢（模型下载 50~150MB）
  • 推理延迟 1~3 秒，非实时流式
  • 中文质量不如云端专业 ASR

Whisper-Web (transformers.js)

  • 基于 Xenova/transformers.js，浏览器端运行 Whisper
  • Whisper-tiny 推理约 3~5 秒，非实时
  • 零 API 成本，完全客户端运行
  • 中文识别质量中等，不如国产 ASR
  • 模型文件较大（tiny: 75MB, base: 150MB）
  • 对设备性能要求高
  • 非流式输出，用户体验差
💡

适用场景

WASM方案适合对隐私要求极高或完全离线的场景。对于本项目需要实时交互的制单场景，体验不如云端方案。

05
开源模型自建后端 API
Qwen3-ASR / FunASR — 自部署推理服务
长期方案

Qwen3-ASR（2026 新秀）

  • 阿里通义千问 2026年1月开源，Apache 2.0 可商用
  • 1.7B / 0.6B 两个规格，52 种语言+方言
  • 开源 SOTA，性能直逼顶级闭源模型
  • 10 秒处理 5 小时音频，支持流式识别
  • 单 GPU 推理延迟 < 500ms
  • 需部署 GPU 服务器（~3~5元/h）
  • MVP 阶段部署成本高于云 API

FunASR（阿里达摩院开源）

  • Paraformer 模型，中文识别质量优秀
  • 支持流式识别、标点恢复、语音端点检测
  • 支持自定义热词
  • CPU 也可运行，部署门槛相对低
  • 社区活跃，文档完善
  • 需部署服务，前端通过 WebSocket 对接
  • 量大时自建成本才优于云 API
🚀

长期价值

当调用量增长到一定规模，自建方案的单次识别成本将远低于云 API。Qwen3-ASR + FunASR 是产品化阶段的最佳长期方案。

04

分阶段推荐方案

不同阶段有不同优先级：MVP追求零成本快速验证，产品化追求质量与可控性，规模化追求成本最优。

MVP 阶段 Week 1-6

Coze 语音插件 + 阿里云 ASR 双轨验证

MVP阶段采用双轨并行策略：Coze语音插件零成本跑通全流程，同时用阿里云ASR做对比测试，验证ASR质量对制单准确率的影响。

方案A（零成本快速验证）：
Coze对话界面 → Coze内置语音插件 → ASR转写 → LLM提取 → 单据生成

方案B（质量优先验证）：
自定义H5页面 → 阿里云ASR(WebSocket) → 流式文本 → Coze Bot API → 单据生成
零成本启动 双轨对比 热词验证
产品化阶段 v0.2+

阿里云 ASR 为主 + Qwen3-ASR 备选

产品化阶段以阿里云ASR为主力。通用SaaS场景下，因热词配额限制，专业术语识别率提升依赖拼音索引匹配在后端兜底；大客户专属场景可启用热词功能做个性化优化。当调用量增长后，Qwen3-ASR自建方案作为成本优化备选。

浏览器前端 → 阿里云ASR(主) / Qwen3-ASR自建(备) → 流式文本 → 后端LLM → 单据生成
生产级质量 热词优化 成本可控
🎯

核心决策逻辑

为什么选阿里云ASR而不是讯飞？ 三个关键理由：
1. 热词功能：阿里云支持运行时动态添加热词（客户名/产品名），讯飞需预上传词库且生效慢
2. Paraformer性价比：阿里云百炼Paraformer仅0.288元/小时，是所有云ASR中最便宜的
3. 浏览器端SDK：阿里云提供官方JavaScript SDK，支持浏览器端WebSocket直连，减少后端中转

SaaS场景补充说明（2026-05-12）：上述热词优势在单租户/私有化部署场景下成立。在通用SaaS多租户场景下，热词配额限制使其无法作为通用方案，需依赖拼音索引匹配在后端兜底。热词方案保留为大客户专属优化能力。

语音制单数据流（推荐方案）

STEP 1

MediaRecorder API 采集麦克风音频，PCM 16kHz 格式

STEP 2

实时推送音频帧至阿里云ASR，携带热词参数

STEP 3

STEP 4

STEP 5

客户库/产品库匹配校验，生成格式化单据草稿

关键细节：阿里云 ASR 热词功能

这是本项目最需要关注的 ASR 能力。业务场景中大量出现客户名、产品名等专业术语，通用ASR难以准确识别。阿里云支持运行时动态添加热词，可将客户名/产品名注入ASR引擎，识别准确率从约70%提升至95%以上。

SaaS适配性限制（2026-05-12补充）：热词配额限制（单表500个/10表共5000个）无法覆盖SaaS多租户场景。通用场景以拼音索引匹配作为兜底方案，热词仅用于大客户专属优化。

// 阿里云ASR WebSocket连接 — 携带热词参数 const params = { appkey: 'your-appkey', format: 'pcm', sample_rate: 16000, enable_intermediate_result: true, // 关键：动态热词，提升专业术语识别率 vocabulary: [ '深圳华创科技', 'A3打印纸', 'B5笔记本', '月结30天' ] };

结论

MVP阶段无论选哪个云ASR，成本都可忽略不计（<15元/月）。真正决定选型的因素是中文识别质量和热词/自定义词库支持。阿里云ASR在这两个维度均表现最优，且Paraformer模型0.288元/小时的极致性价比为后续增长留足了空间。当月调用量超过约200小时后，切换到Qwen3-ASR自建方案可进一步降低成本。

SaaS场景补充（2026-05-12）：在通用SaaS多租户场景下，热词方案因配额限制暂不适用，拼音索引匹配是通用场景的核心兜底机制。热词方案保留为大客户个性化优化的可选项。
