获取历史最近价格的方法

智能制单 · 一键价格（B 来源）· 调试回溯与最终方案
模块：dexiedb/index.html  |  目标：通过 load_data 接口获取"当前客户 × 当前产品"的最近成交价

一、需求背景

在智能制单界面，用户已经完成：

  • 选择客户 → 拿到 customer.cu_id（客户ID）
  • 录入产品 → 通过拼音匹配拿到 product.matchedId（产品ID）、matchedName、matchedSku

点击"一键价格" → 切换到 B 来源（历史成交） → 需要对当前客户 + 当前每个产品取最近一条历史成交价，回填到价格列。

二、API 接口

项目说明
请求方式POST /system/api.xt，body 为 JSON（不要用 GET，规避 where/order 里的空格/中文编码问题）
cmdload_data
dtnamegoods（交付计划/订单明细表）
fieldid,name,cu_id,un_price,micro_zk,sum
wherecu_id=客户ID AND (name=产品ID1 OR name=产品ID2 OR ...)
orderid desc（按记录主键倒序，最新在前）
limit不传（一次取所有匹配，前端按产品分组取首条）

请求体示例：

{
  "cmd":   "load_data",
  "dtname":"goods",
  "field": "id,name,cu_id,un_price,micro_zk,sum",
  "where": "cu_id=107 AND (name=6 OR name=8)",
  "order": "id desc"
}

三、响应字段语义（重要！）

坑 请求 where 里的 name=6 看上去是"产品ID=6"，但响应里 name 字段返回的不是 ID，而是人类可读的完整规格名。

实际响应示例（见 历史价格返回值.json）：

字段实际含义容易误解为

name 完整规格名（如 "金士顿CF(8G)/CF8G[个]"）
= 基础产品名 + "/" + SKU + "[单位]"		 产品 ID ❌
cu_id 客户名称（如 "〖飞奥德〗"） 数字客户 ID ❌
un_price 单价（字符串数字） —
micro_zk 折扣，格式 "-RMB21.12(89%)" 或 " "（空格=无折扣） —
sum 成交金额（= un_price × 数量 × 折扣） —

四、调试过程（踩坑 → 修复）

错误 1
GET 请求的 queryString 编码问题

症状 where 含空格/中文时，encodeURIComponent 漏写或重复转义，导致 where=name=6%20and%20cu_id=107 解析为单条条件，and 后半段被吞。

根因 URL 拼接不规范，特殊字符依赖多次手工转义。

修复 改用 POST + Content-Type: application/json，由后端 JSON.parse 解析 where/order/limit/field。

错误 2
用了不存在的字段 pro_id

症状 响应里没有 pro_id，row.pro_id 始终 undefined，分组键全部 "undefined"。

修复 改用 goods 表实际存在的字段：id,name,cu_id,un_price,micro_zk,sum。

错误 3
把响应 name 当产品 ID 解析

症状 用 row.name（完整规格名"金士顿CF(8G)/CF8G[个]"）去做产品匹配，等值比较永远不成立。

修复 意识到 row.name 是"基础名 + "/" + SKU + "[单位]""，需要先剥掉单位再匹配，且匹配的是"我们的产品品名 + SKU"，而不是产品 ID。

错误 4
把响应 cu_id 当数字 ID 与当前 customer.cu_id 比对

症状 响应 cu_id="〖飞奥德〗"（客户名称），当前 customer.cu_id=107（数字 ID），永远不等，误以为"响应数据不属于当前客户"。

修复 客户过滤放在 请求 where 里（cu_id=107 用数字 ID），不在响应里做二次过滤；响应里的 cu_id 只用于展示。

错误 5
产品匹配只做了"去单位后精确等值"，命中率 0

症状 我们的产品 matchedName="金士顿CF(8G)"，响应 stripped="金士顿CF(8G)/CF8G"，两者不相等，匹配不上。

根因 我们的产品名只存了"基础品名"，缺少 SKU 后缀。

修复 在构造匹配键时，把产品品名补充为"品名 + '/' + SKU"，与 goods.name 剥单位后的格式保持一致：

function _getFullProductName(p) {
  if (!p) return '';
  var name = (p.matchedName || p.originalName || p.pro_name || p.name || '').toString().trim();
  var sku  = (p.matchedSku || p.newSku || '').toString().trim();
  if (sku && sku !== '-' && sku !== '无') return name ? (name + '/' + sku) : '';
  return name;
}
错误 6
只匹配上 1 个产品，另 1 个（"爱国者"）没匹配上

症状 4 条响应 → 应该 2 个产品各命中 1 条 → 实际只命中 1 个（金士顿CF），爱国者迷你王始终未命中。

根因排查 起初怀疑 matchedSku 没赋值，于是加诊断日志打印 matchedSku 和完整的 ourNameKeys。

修复 日志显示 SKU 是有的，但部分产品 ourNameKeys 里确实缺少某些变体，匹配漏掉。

为此进一步把匹配策略从 1 层扩到 4 层兜底（见第五节）。

错误 7
缓存脏数据：第二次查询时 grouped 缺失新加产品

症状 用户增删产品后再次点"一键价格"，UI 仍显示旧的 grouped 结果，新加的产品没有"无记录"占位。

根因 _priceCache.goods_history 在第一次查询后被缓存，后续直接复用，未与 currentProducts 对齐。

修复 给缓存加上 productIds 快照比对，不一致时强制重建：

if (_priceCache.goods_history !== null) {
  var cachedKey = _priceCache.goods_history_productIds
    ? _priceCache.goods_history_productIds.join(',') : '';
  var currentKey = productIds.slice().sort().map(String).join(',');
  if (cachedKey === currentKey) {
    return { ok: 1, grouped: _priceCache.goods_history };
  }
  _priceCache.goods_history = null;   // 强制重建
}

五、最终方案

5.1 核心调用链

UI 切到 B → _fetchAndCacheHistory(customerId) → _loadHistoryPrices(customerId, productIds) → POST load_data (goods 表) → rows.forEach → _findOurProductByRowName(rowName) // 4 层匹配 → grouped[productKey] = 首条 → _renderHistorySummary(grouped)

5.2 辅助函数：去末尾单位

响应 name 末尾常带 [个]、[套]、（个）、【套】 等单位，匹配前先剥掉：

function _stripTrailingUnit(s) {
  if (!s || typeof s !== 'string') return '';
  return s.replace(/[\[【（(][^)\]】]*[\]】）)]\s*$/, '').trim();
}

// 示例
_stripTrailingUnit('金士顿CF(8G)/CF8G[个]')
  → '金士顿CF(8G)/CF8G'
_stripTrailingUnit('爱国者迷你王 商务型L8202(16G)/IP23[套]')
  → '爱国者迷你王 商务型L8202(16G)/IP23'

5.3 辅助函数：构造我们的"完整产品名"

把拼音匹配产物的 matchedName + matchedSku 拼成 品名/SKU，与 goods.name 剥单位后的格式一致：

function _getFullProductName(p) {
  if (!p) return '';
  var name = (p.matchedName || p.originalName || p.pro_name || p.name || '').toString().trim();
  var sku  = (p.matchedSku  || p.newSku       || '').toString().trim();
  if (sku && sku !== '-' && sku !== '无') return name ? (name + '/' + sku) : '';
  return name;
}

5.4 核心：4 层匹配策略

用 ourNameList 装下每个产品多个变体键（full / matchedName / originalName / matchedCode / matchedId），逐层试：

function _findOurProductByRowName(rowName) {
  var stripped = _stripTrailingUnit(rowName);

  // (a) 去单位后精确等值（首选，最稳）
  for (var i = 0; i < ourNameList.length; i++) {
    if (ourNameList[i].key === stripped) {
      return { product: ourNameList[i].product, matchType: 'exact-stripped', keyKind: ourNameList[i].kind };
    }
  }
  // (b) 原值精确等值（响应本身没单位时）
  for (var i = 0; i < ourNameList.length; i++) {
    if (ourNameList[i].key === rowName) {
      return { product: ourNameList[i].product, matchType: 'exact-raw', keyKind: ourNameList[i].kind };
    }
  }
  // (c) 双向"去单位后"前缀（SKU 缺失/多带尾巴时兜底）
  for (var i = 0; i < ourNameList.length; i++) {
    var key = ourNameList[i].key;
    if (key && key.length > 0) {
      if (stripped.indexOf(key) === 0)              return { product: ourNameList[i].product, matchType: 'prefix-stripped',            keyKind: ourNameList[i].kind };
      if (key.indexOf(stripped) === 0 && stripped.length >= 2)
                                                return { product: ourNameList[i].product, matchType: 'reverse-prefix-stripped',  keyKind: ourNameList[i].kind };
    }
  }
  // (d) 双向原值前缀（最后兜底）
  for (var i = 0; i < ourNameList.length; i++) {
    var key = ourNameList[i].key;
    if (key && key.length > 0) {
      if (rowName.indexOf(key) === 0)              return { product: ourNameList[i].product, matchType: 'prefix-raw',            keyKind: ourNameList[i].kind };
      if (key.indexOf(rowName) === 0 && rowName.length >= 2)
                                                return { product: ourNameList[i].product, matchType: 'reverse-prefix-raw',  keyKind: ourNameList[i].kind };
    }
  }
  return null;
}

5.5 分组取首条

服务端已 order by id desc，故遍历 rows 时，每个 productKey 第一次出现的那条就是最近成交：

var grouped = {};
for (var i = 0; i < currentProducts.length; i++) {
  grouped[String(currentProducts[i].matchedId)] = null;   // 初始化所有产品
}
for (var j = 0; j < rows.length; j++) {
  var row = rows[j];
  var matchResult = _findOurProductByRowName(String(row.name).trim());
  if (!matchResult) { unmatchedRowNames.push(row.name); continue; }
  var productKey = String(matchResult.product.matchedId);
  if (grouped[productKey] === null) {                   // 仅取首条
    grouped[productKey] = {
      recId:     row.id,
      proId:     matchResult.product.matchedId,
      proName:   _getFullProductName(matchResult.product) || row.name,
      matchType: matchResult.matchType,
      un_price:  _toPriceNum(row.un_price),
      micro_zk:  row.micro_zk || '',
      discount:  _parseDiscount(row.micro_zk),
      sum:       _toPriceNum(row.sum)
    };
  }
}

5.6 缓存失效检查

产品列表变化时强制重建 grouped：

if (_priceCache.goods_history !== null) {
  var cachedKey  = _priceCache.goods_history_productIds
                 ? _priceCache.goods_history_productIds.join(',') : '';
  var currentKey = productIds.slice().sort().map(String).join(',');
  if (cachedKey === currentKey) return { ok: 1, grouped: _priceCache.goods_history };
  _priceCache.goods_history = null;     // 强制重建
}

六、诊断日志

在 _fetchAndCacheHistory 末尾打印完整诊断信息，便于定位匹配失败：

console.log('[一键价格/B] 分组完成：', {
  totalProducts:     currentProducts.length,
  responseRows:      rows.length,                          // 服务端实际返回几条
  matchedProducts:   matchedCount,
  matchedNames:      matchedNames,                         // 每条 row 匹配到了什么
  unmatchedRowNames: Array.from(new Set(unmatchedRowNames)),  // 未命中的 row name
  ourProducts: ourMatchedNames,                            // 我们的产品概况（含 matchedSku）
  ourNameKeys:  ourNameList.map(function (it) {            // 我们构造的所有匹配键
    return { key: it.key, kind: it.kind, pIdx: currentProducts.indexOf(it.product) };
  })
});

Tip 出现匹配异常时，先看：

  • responseRows：是否真的返回了多条？
  • ourProducts[].matchedSku：SKU 是不是真的没值？
  • ourNameKeys 里有没有目标产品的 full 键（品名/SKU）？
  • unmatchedRowNames：哪条 row 没匹配上，对应的 stripped 是什么？

七、注意事项 & 易踩的坑

坑说明规避
GET 拼接 where 含空格/中文的 where 容易被 encodeURIComponent 转义错 统一用 POST + JSON，由后端 JSON.parse
响应 name 含单位 [个][套] 等单位挂在末尾，精确等值必失败 用 _stripTrailingUnit 剥掉
我们的产品没有 SKU 只存品名，缺 /SKU 后缀，与 goods.name 对不上 用 _getFullProductName 拼成 品名/SKU
缓存脏数据 产品列表增删后，缓存 grouped 仍为旧值 缓存加 productIds 快照比对，不一致时强制重建
把 row.id 当产品 ID id 是记录主键，与产品无关 产品 ID 始终用 matchedProduct.matchedId
把 row.cu_id 当客户 ID cu_id 是客户名称，不是数字 ID 客户过滤放在请求 where 里；响应用作展示
同产品多条历史 同一产品可能有多条历史记录 order by id desc + 首次出现即取首条
