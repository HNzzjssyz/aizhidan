1. 30 秒上手（TL;DR）

📌 一句话原则： 修改 dexiedb/ 根目录下的 4 个源文件 → 运行 _build_split.py → dev/ 和 prod/ 自动同步。
最终开发目录
SRC dexiedb/
拼音试验/dexiedb/ — 4 个源文件，所有修改都在这里进行
开发版（深度调试）
DEV dexiedb/dev/
与源文件完全一致，保留所有中文注释，行号清晰
发布版（实际部署）
PROD dexiedb/prod/
去掉所有 JS/HTML 注释，体积更小，作为最终发布件
同步脚本
PY _build_split.py
一键把 4 个源文件分离为 dev/ 和 prod/

4. 代码修改 → 同步到 Pro 流程

所有代码修改都遵循以下 3 步流程：

修改源文件
在 dexiedb/ 根目录下打开 4 个源文件之一（如 index.html），使用任意编辑器修改。
⚠️ 不要去修改 dev/ 或 prod/ 里的同名文件！
执行同步脚本
打开终端，进入 dexiedb/ 目录，运行：
cd dexiedb
python3 _build_split.py
脚本会自动：① 复制源文件到 dev/（带注释）；② 去注释后写入 prod/（精简版）。
验证同步结果
打开 dev/index.html 检查改动是否生效；打开 prod/index.html 确认注释已被去除。
💡 调试问题用 dev/；给客户/上线部署用 prod/。

同步脚本支持的模式

命令 说明 使用场景
python3 _build_split.py 直接执行，覆盖 dev/ 和 prod/ 最常用，每次改完代码跑一次
python3 _build_split.py --dry-run 只打印将执行的动作，不写文件 不确定脚本行为时先跑一遍看看
python3 _build_split.py --watch 监听模式：源文件变化时自动重建（Ctrl+C 退出） 长时段开发，不想每次手动跑脚本
python3 _build_split.py --init 监听 + 立即构建一次 启动开发时使用

Mac 一键启动（可选）

项目根目录下的 一键启动监听.command 是 Mac 下的双击启动脚本，等价于 python3 _build_split.py --watch --init。运维人员可以双击该文件直接进入监听模式。

5. dev/ vs prod/ 对比

同样的 4 个源文件，经过 _build_split.py 处理后，在 dev/ 和 prod/ 中呈现不同形态：

维度 dev/ 开发版 prod/ 发布版
JS 注释 ✅ 完整保留（含中文说明、版本号、修改原因） ❌ 全部去除（// 单行 + /* */ 多行）
HTML 注释 ✅ 完整保留 ❌ 全部去除（<!-- ... -->）
行号 ✅ 与源文件一一对应 ⚠️ 行号可能偏移（注释去除后行会前移）
连续空行 ✅ 保留 ❌ 合并为单个空行
字符串/正则 ✅ 保留 ✅ 保留（状态机保护，不影响字面量）
体积 = 源文件 略小（通常 2-10% 压缩）
用途 开发调试、问题定位、阅读代码 实际部署、给客户演示、文件分发
运维角色 排错查阅 最终交付件

6.2 常见问题

Q1：我改了 dev/ 里的文件，为什么改动没生效？
A：dev/ 是脚本自动生成的，不要修改。下次运行 _build_split.py 会被源文件覆盖。所有改动改 dexiedb/ 根目录的源文件。
Q2：prod/ 里有一段中文注释怎么没去掉？
A：脚本只去除 // 单行、/* */ 多行 JS 注释和 <!-- --> HTML 注释。如果注释写在了字符串字面量里（"// 我是字符串"），状态机会保护它不被误删。检查一下是不是被包在引号内了。
Q3：源文件改完了，但 dev/ 还是旧的？
A：忘记跑 _build_split.py 了。修改完源文件后必须运行一次同步脚本（或使用 --watch 监听模式）。
Q4：prod/ 里的代码行号对不上源文件，调试时怎么定位？
A：调试永远用 dev/，因为 prod/ 去掉了注释，行号会偏移。prod/ 只用于最终发布。
Q5：可以删除 dev/ 和 prod/ 重新生成吗？
A：可以。删除两个目录后跑 _build_split.py 会自动重建。但一般没必要——脚本每次运行是覆盖而不是追加。
Q6：怎么回滚到某个旧版本？
A：项目里有 14+ 个历史备份目录（如 0612备份历史成交改算法/）。找到对应日期的备份，把里面的 4 个文件复制回 dexiedb/ 根目录，再跑一次 _build_split.py 即可。

7. 深度运维等级（5 级）

不同运维场景对应不同的能力等级，按需深入：

等级 角色 需要的能力 涉及目录
⭐ 普通用户 / 客户 打开 prod/index.html 使用 prod/ （只读）
⭐⭐ 业务运维 能看懂错误提示、收集日志、上传备份 prod/、备份目录
⭐⭐⭐ 技术运维 能跑同步脚本、对比 dev/prod、定位简单问题 上述 + dev/、_build_split.py
⭐⭐⭐⭐ 开发维护 能修改源文件、跑监听模式、阅读注释 上述 + dexiedb/ 4 源文件
⭐⭐⭐⭐⭐ 架构师 能修改同步脚本、调整产品目录、扩展新源文件 全部 + _build_split.py 源码

各级别的最小操作集

⭐ 普通用户

  • 双击 dexiedb/prod/index.html 或部署到 Web 服务器
  • 使用 AI 制单主界面，无需关心任何开发细节

⭐⭐ 业务运维

  • 用户报障时：打开 prod/index.html 复现
  • 需要看用户数据状态：浏览器 F12 看控制台日志
  • 必要时从 dexiedb/ 内的 14+ 备份目录找回历史版本

⭐⭐⭐ 技术运维

  • 遇到代码相关问题：直接打开 dexiedb/dev/index.html 调试（保留完整中文注释，行号与源一致）
  • 代码改动后：跑 python3 _build_split.py 同步
  • 持续开发：使用 python3 _build_split.py --watch 自动重建
  • 验证产物：diff dexiedb/index.html dexiedb/dev/index.html 应无输出

⭐⭐⭐⭐ 开发维护

  • 使用任意编辑器（VSCode、Sublime 等）打开 dexiedb/ 根目录的 4 个源文件
  • 修改后必须跑 _build_split.py（除非开了 --watch）
  • 阅读 关联文档 了解设计思路和接口规范

⭐⭐⭐⭐⭐ 架构师

  • 可修改 _build_split.py：
    • SRC_FILES：要同步的文件清单（默认 4 个）
    • strip_js_comments / strip_html_comments：注释剥离逻辑（状态机）
    • process_js / process_html：处理流水线
  • 新增源文件：编辑 SRC_FILES 数组即可，下次运行自动同步
  • 新增同步目录：编辑 DEV_DIR / PROD_DIR 或扩展 _build_once
