一、项目定位

CozeFlow Input 是一个独立的前端组件项目，为所有基于扣子工作流的应用提供统一的输入交互面板。它封装了文字对话、语音输入、截图粘贴、文件上传四种输入方式，以及工作流 API 调用、消息管理、配置管理等通用逻辑，业务方只需关注工作流的输入参数和输出处理。

核心价值： 一次开发，所有扣子工作流项目复用。业务方无需重复开发输入交互，只需配置 workflow_id 和输出回调即可接入。
维度 说明
项目性质 独立前端组件，不绑定任何业务逻辑
交付物 单 HTML 文件（零构建依赖）+ 可选 JS 模块文件
复用方式 iframe 嵌入 / script 标签引入 / 源码拷贝
适用场景 任何需要通过扣子工作流 API 接收用户输入并获取结构化输出的前端应用
二、技术栈
设计原则： 零构建依赖，所有库通过 CDN 引入，单 HTML 文件即可运行。不使用框架（React/Vue），纯 Vanilla JS，确保最大兼容性和最小接入成本。
技术 用途 引入方式 大小 必要性
Vanilla JS (ES5+) 核心逻辑 内联 0 必须
CSS Custom Properties 主题/样式 内联 0 必须
remixicon 图标 CDN CSS ~80KB 必须
SheetJS (xlsx) Excel 解析 CDN script ~500KB 可选（按需加载）
mammoth.js Word 解析 CDN script ~100KB 可选（按需加载）
MediaRecorder API 录音 浏览器原生 0 语音输入必须
Clipboard API 粘贴截图 浏览器原生 0 截图粘贴必须
按需加载策略： SheetJS 和 mammoth.js 仅在用户首次上传对应文件类型时动态加载，不纳入首屏资源，减少初始加载时间。

cozeflow-input/ ├── index.html ← 完整独立版（单文件，可直接运行） ├── cozeflow-input.js ← 核心模块（可被外部页面引入） ├── cozeflow-input.css ← 样式文件（可被外部页面引入） ├── demo.html ← 演示页面（接入智能制单业务） └── README.md ← 使用文档

四、模块架构

核心逻辑拆分为 6 个独立模块，每个模块职责单一、可独立测试、可按需加载。

WorkflowClient
核心模块
工作流 API 调用封装，处理鉴权、请求、响应解析、超时重试、流式输出
run(params) 同步执行
runStream(params) 流式执行
uploadFile(blob) 上传文件
transcribeAudio(blob) 语音转文字
setConfig({workflow_id, token}) 配置
MessageManager
核心模块
消息列表管理，维护对话历史，支持用户/AI/系统三种消息类型，自动滚动
addUser(text) 添加用户消息
addAI(text, data) 添加AI消息
addSystem(text, type) 添加系统消息
clear() 清空历史
getHistory() 获取对话历史
VoiceInput
输入模块
语音录制与识别，支持 Coze API 和浏览器原生两种识别引擎
start() 开始录音
stop() 停止录音
onResult(callback) 识别结果回调
getState() 获取录音状态
setEngine('coze'|'native') 切换引擎
ImageCapture
输入模块
截图粘贴捕获，监听 paste 事件提取图片，支持拖拽上传图片
startListening() 开始监听粘贴
stopListening() 停止监听
onCapture(callback) 图片捕获回调
enableDragDrop(el) 启用拖拽上传
FileParser
输入模块
文件解析，按需加载 SheetJS/mammoth.js，本地解析 Excel/Word 提取文本
parseExcel(file) 解析Excel
parseWord(file) 解析Word
parse(file) 自动识别类型
isSupported(type) 检查支持类型
ConfigManager
核心模块
配置管理，持久化存储 workflow_id / token / 引擎偏好等，支持导入导出
get(key) 获取配置
set(key, value) 设置配置
save() 持久化到 localStorage
load() 从 localStorage 加载
export() / import(data) 导入导出

模块依赖关系：

依赖方向：上层 → 下层 UI 层（HTML/CSS） ↓ 调用 输入模块 VoiceInput / ImageCapture / FileParser ↓ 输出文本/文件 核心模块 WorkflowClient ← MessageManager ↓ 调用 ↑ 记录 API 层 Coze Workflow API / File API / Audio API ConfigManager 被所有模块共享读写

六、核心 API 设计

WorkflowClient — 工作流调用封装：

var client = new WorkflowClient({ baseUrl: 'https://api.coze.cn', token: 'pat_xxx', workflowId: '73664689170551****', timeout: 60000, onBeforeSend: function(params) { /* 发送前钩子 */ }, onAfterReceive: function(result) { /* 接收后钩子 */ } }); // 同步执行工作流 var result = await client.run({ user_input: '帮华创科技下个单', image_url: '{"file_id":"xxx"}' // 可选 }); // result = { code: 0, data: "{...}", debug_url: "...", usage: {...} } // 流式执行工作流 client.runStream({ user_input: '帮华创科技下个单' }, { onMessage: function(chunk) { /* 流式消息 */ }, onComplete: function(result) { /* 完成 */ }, onError: function(err) { /* 错误 */ } }); // 上传文件 var fileResult = await client.uploadFile(imageBlob); // fileResult = { file_id: 'xxx' } // 语音转文字 var transcript = await client.transcribeAudio(audioBlob); // transcript = '帮华创科技下个单A3打印纸100箱'

业务方接入接口（对外暴露的最小 API）：

// 初始化面板 var panel = new CozeFlowInput({ container: '#right-panel', // 挂载容器 workflowId: '73664689170551****', // 工作流ID token: 'pat_xxx', // PAT Token inputs: { // 启用的输入方式 text: true, voice: true, image: true, file: true }, voiceEngine: 'coze', // 'coze' | 'native' onResult: function(data) { // 工作流返回回调 // data = 工作流结束节点输出的 JSON 对象 // 业务方在此处理填充表单等逻辑 fillOrderForm(data); }, onError: function(err) { // 错误回调 console.error(err); } }); // 程序化发送消息 panel.send('帮华创科技下个单'); // 获取对话历史 var history = panel.getHistory(); // 更新配置 panel.setConfig({ workflowId: 'new-id' });
七、输入方式详细设计
7.1 文字输入
模块：MessageManager + WorkflowClient

流程：用户在输入框输入文字 → 点击发送/按回车 → 调用 WorkflowClient.run() → 返回结果触发 onResult 回调 → AI 消息气泡展示结果摘要

关键逻辑：

逻辑点实现
发送防抖发送中禁用按钮，防止重复提交
超时处理60 秒未返回则提示超时，支持重试
结果解析尝试 JSON.parse(result.data)，失败则作为纯文本展示
JSON 预览AI 消息气泡中可展开查看完整 JSON
Token 统计系统消息显示本次消耗 Token 数
7.2 语音输入
模块：VoiceInput + WorkflowClient

流程：点击🎤 → MediaRecorder 录制 WebM → 点击停止 → 调用 WorkflowClient.transcribeAudio() → 识别文本回填输入框 → 自动触发工作流

双引擎设计：

维度Coze API 引擎浏览器原生引擎
识别准确率高（专业语音模型）一般（Chrome 中文尚可）
成本消耗 Token免费
浏览器兼容所有现代浏览器仅 Chrome/Edge
实时性录音结束后识别支持实时中间结果
网络要求需要需要（Chrome 在线模式）
适用场景生产环境快速调试/离线备选

关键逻辑：

逻辑点实现
权限检查首次录音前检查 navigator.mediaDevices.getUserMedia，无权限则提示
录音格式MediaRecorder + audio/webm，兼容 Chrome/Edge/Firefox
最大时长60 秒自动停止，防止录音过长
中间结果浏览器原生引擎支持 oninterimresult，实时显示在输入框
自动提交识别完成后自动触发 panel.send(transcript)
7.3 截图粘贴
模块：ImageCapture + WorkflowClient

流程：用户 Ctrl+V 粘贴截图 → paste 事件捕获图片 Blob → 上传到 Coze 文件 API 获取 file_id → 调用 WorkflowClient.run({ image_url }) → 工作流内部 LLM 视觉节点识别图片内容

关键逻辑：

逻辑点实现
粘贴监听document.addEventListener('paste', handler)，提取 clipboardData.items 中 type 为 image/* 的项
拖拽上传面板区域监听 dragover + drop，提取 dataTransfer.files 中的图片
图片预览消息列表中展示缩略图，点击可放大查看
文件上传POST /v1/files/upload，FormData 格式，获取 file_id
参数传递image_url: '{"file_id":"xxx"}'，工作流开始节点需定义 image_url 参数
工作流分支工作流内通过条件分支判断 image_url 是否存在，有则走 LLM 视觉识别路径
7.4 文件上传
模块：FileParser + WorkflowClient

流程 A（本地解析）：用户选择文件 → FileParser 本地解析提取文本 → 文本作为 user_input 传入工作流

流程 B（上传解析）：用户选择文件 → 上传到 Coze 文件 API → file_id 传入工作流 → 工作流内部用插件解析

关键逻辑：

逻辑点实现
文件选择<input type="file" accept=".xlsx,.xls,.docx,.doc">，支持点击和拖拽
Excel 解析按需加载 SheetJS CDN，XLSX.read(arrayBuffer) → 遍历 sheet → 拼接单元格文本
Word 解析按需加载 mammoth.js CDN，mammoth.extractRawText(arrayBuffer) → 获取纯文本
文本截断解析文本超过 10000 字符时截断并提示，避免超出工作流请求限制
预览确认解析后展示前 500 字预览，用户确认后提交
按需加载SheetJS/mammoth.js 仅在首次使用时动态 document.createElement('script') 加载
八、工作流侧配合

CozeFlow Input 的前端输入需要工作流侧的配合设计，确保各种输入方式的数据能被正确接收和处理。

工作流开始节点参数定义： { "user_input": { "type": "string", "required": true, "description": "用户输入的文本内容（文字/语音识别/文件解析结果）" }, "image_url": { "type": "string", "required": false, "description": "截图的 file_id，格式：{\"file_id\":\"xxx\"}" }, "file_id": { "type": "string", "required": false, "description": "上传文件的 file_id，格式：{\"file_id\":\"xxx\"}" } }

工作流分支设计：

工作流节点编排（含分支）： 开始节点 → 条件分支 ├─ image_url 有值 → LLM 视觉节点（识别图片内容）→ 合并节点 ├─ file_id 有值 → 文件解析插件 → 合并节点 └─ 仅 user_input → 合并节点 → LLM 主节点（解析制单意图，输出 JSON v1.1）→ 结束节点
工作流侧的优势： 分支逻辑在工作流中可视化编排，比在智能体 Prompt 中用条件判断更可控、更稳定。 图片识别走 LLM 视觉节点，文件解析走插件节点，各司其职。
