一、方案背景

当前智能制单采用"扣子智能体 + 剪贴板监听"方案，用户在 Coze Bot 对话窗口中输入需求，AI 返回 JSON，用户手动复制后由前端剪贴板监听捕获并填充表单。该方案存在以下问题：

当前痛点： 剪贴板监听依赖用户手动复制操作，体验割裂； navigator.clipboard.readText() 需浏览器授权且兼容性差； 轮询有 3 秒延迟； SDK 浮动窗口嵌入需 DOM 劫持，版本升级后可能失效； AI 输出格式不可控，需正则提取 JSON。

扣子工作流 API 提供了另一种集成路径：前端直接调用 POST /v1/workflow/run，传入用户输入，工作流返回结构化 JSON，前端直接解析填充。无需剪贴板中转，数据传递 100% 可靠。

核心收益： API 直返结构化 JSON，消除剪贴板依赖； 工作流结束节点可约束输出格式； UI 完全自主，不再依赖 SDK 浮窗； debug_url 可视化每步执行，调试友好。
二、架构对比
当前方案
智能体 + 剪贴板
  • SDK 自带聊天 UI、语音、文件上传
  • 数据传递依赖剪贴板，需手动复制
  • AI 输出格式不可控
  • 浮窗嵌入需 DOM 劫持
  • 轮询延迟 3 秒
  • 浏览器剪贴板权限问题
推荐方案
工作流 API 直调
  • API 直返结构化 JSON，程序化获取
  • 工作流结束节点约束输出格式
  • UI 完全自主，无 DOM 劫持
  • debug_url 可视化调试
  • 无浏览器权限问题
  • 输入交互需自研（文字/语音/截图/文件）
当前方案数据流：
用户输入 → Coze Bot SDK → AI 返回文本 → 用户手动复制 → 剪贴板监听 → 表单填充
工作流方案数据流：
用户输入 → 前端预处理 → POST /v1/workflow/run → 工作流执行 → 结构化 JSON 直返 → 表单填充
三、扣子工作流设计

在扣子平台创建工作流，将现有智能体的 Prompt 和知识库逻辑迁移为工作流节点。

工作流节点编排：

开始节点 接收 user_input（文本）、image_url（可选）、file_content（可选）
↓
LLM 节点 解析制单意图，提取客户/产品/数量/价格等，输出制单 JSON v1.1
↓
结束节点 输出结构化 JSON 字符串
节点 类型 输入 输出 说明
开始节点 Start user_input (String)
image_url (String, 可选)
file_content (String, 可选)		 — 接收前端传入的用户输入
LLM 解析 LLM 开始节点输出 制单 JSON v1.1 System Prompt 约束输出格式，含拼音字段
结束节点 End LLM 输出 JSON 字符串 直接透传 LLM 输出，前端解析
工作流注意事项： 结束节点不能开启流式输出； 工作流必须已发布才能 API 调用； 非流式模式 90 秒超时，超时需改用流式或异步模式； 若工作流使用数据库节点/变量节点，需传 bot_id 关联智能体。
四、API 集成
接口 方法 地址 说明
执行工作流 POST https://api.coze.cn/v1/workflow/run 同步执行，90 秒内返回
执行工作流（流式） POST https://api.coze.cn/v1/workflow/stream_run 流式输出，适合长时间工作流
查询异步结果 GET https://api.coze.cn/v1/workflow/runs/{execute_id} 异步模式查询执行结果
上传文件 POST https://api.coze.cn/v1/files/upload 上传图片/文件，获取 file_id
语音转文字 POST https://api.coze.cn/v1/audio/transcriptions 语音识别，返回文本

执行工作流请求示例：

// POST /v1/workflow/run // Header: Authorization: Bearer {PAT_TOKEN} { "workflow_id": "73664689170551****", "parameters": { "user_input": "帮华创科技下个单，A3打印纸100箱，铅笔200支5毛" } } // 返回 { "code": 0, "data": "{\"doc_type\":\"销售订单\",\"customer_name\":\"深圳华创科技有限公司\",\"customer_pinyin\":\"shen_zhen_hua_chuang_ke_ji_you_xian_gong_si\",\"products\":[{\"name\":\"A3打印纸\",\"pinyin\":\"A3_da_yin_zhi\",\"qty\":100,\"unit\":\"箱\"}]}", "debug_url": "https://www.coze.cn/work_flow?execute_id=...", "usage": { "token_count": 150 } }

前端调用封装：

async function runWorkflow(params) { const response = await fetch('https://api.coze.cn/v1/workflow/run', { method: 'POST', headers: { 'Authorization': 'Bearer ' + PAT_TOKEN, 'Content-Type': 'application/json' }, body: JSON.stringify({ workflow_id: WORKFLOW_ID, parameters: params }) }); const result = await response.json(); if (result.code === 0) { const orderData = JSON.parse(result.data); fillOrderForm(orderData); // 直接填充左侧表单 } }
五、输入方式设计

工作流方案下，右侧交互区需自研四种输入方式。每种方式独立开发，统一通过 runWorkflow() 调用工作流。

文字对话 优先级 P0
用户在输入框中输入制单需求文字，前端调用工作流 API，返回 JSON 后直接填充左侧表单。同时维护消息气泡列表展示对话历史。
实现：输入框 + 发送按钮 + 消息气泡列表
调用：runWorkflow({ user_input: text })
预估代码：200-300 行
语音输入 优先级 P1
用户点击麦克风按钮开始录音，再次点击停止。录音完成后调用语音识别 API 将语音转为文字，识别结果回填到输入框，自动触发工作流调用。
方案 A（推荐）：Coze 语音转文字 API — POST /v1/audio/transcriptions，需 PAT 鉴权，中文识别准确率高
方案 B（备选）：浏览器原生 webkitSpeechRecognition，免费但中文准确率一般，Chrome only
实现：录音按钮 + 录音状态动画 + MediaRecorder API 录制 WebM
调用：录音 → 语音转文字 → runWorkflow({ user_input: transcript })
预估代码：150-200 行
截图粘贴 优先级 P1
用户在页面中粘贴截图（Ctrl+V），前端捕获图片后上传到 Coze 文件 API 获取 file_id，将 file_id 作为参数传入工作流，工作流内部调用 LLM 视觉能力识别图片内容。
实现：监听 paste 事件 → clipboardData.items 提取图片 Blob
上传：POST /v1/files/upload 获取 file_id
调用：runWorkflow({ user_input: '请识别截图中的制单信息', image_url: '{"file_id":"xxx"}' })
预估代码：100-150 行
上传 Excel / Word 优先级 P2
用户选择本地 Excel 或 Word 文件，前端本地解析提取文本内容，将文本作为 user_input 传入工作流。Excel 用 SheetJS 解析，Word 用 mammoth.js 解析。
Excel 解析：SheetJS (xlsx) 库，CDN 引入，本地解析，提取单元格文本
Word 解析：mammoth.js 库，CDN 引入，本地解析，提取纯文本
备选方案：上传到 POST /v1/files/upload，工作流内部用插件解析
调用：解析文本 → runWorkflow({ user_input: extractedText })
预估代码：150-200 行

七、数据流详解

场景 1：文字输入制单

用户输入"帮华创科技下单..." → 前端调用 runWorkflow() → Coze 工作流执行 → 返回 JSON v1.1 → fillOrderForm()

场景 2：语音输入制单

用户点击🎤录音 → MediaRecorder 录制 → Coze 语音转文字 API → 识别文本回填输入框 → 自动触发 runWorkflow() → fillOrderForm()

场景 3：截图粘贴制单

用户 Ctrl+V 粘贴截图 → paste 事件捕获图片 → Coze 文件上传 API → 获取 file_id → runWorkflow({ image_url }) → fillOrderForm()

场景 4：上传 Excel/Word

用户选择文件 → SheetJS/mammoth 本地解析 → 提取文本内容 → runWorkflow({ user_input: text }) → fillOrderForm()

九、风险与应对
风险 影响 应对措施
工作流 API 90 秒超时 高 优化工作流节点数量，控制 LLM 输出长度；超时场景改用流式 API /v1/workflow/stream_run
PAT Token 暴露在前端 高 开发阶段可接受；生产环境需加后端代理，Token 存服务端，前端只调自己的后端接口
语音识别准确率不足 中 优先使用 Coze 语音 API（准确率高）；识别结果回填输入框后用户可手动修正再提交
截图 OCR 识别不准 中 工作流内 LLM 视觉能力做 OCR；识别结果展示在消息列表中，用户可修正后重新提交
Excel/Word 解析兼容性 低 SheetJS 和 mammoth.js 均为成熟库；复杂格式文件建议用户先转为文本再输入
工作流输出格式不稳定 中 在 LLM 节点的 System Prompt 中严格约束 JSON Schema；前端增加容错解析逻辑
