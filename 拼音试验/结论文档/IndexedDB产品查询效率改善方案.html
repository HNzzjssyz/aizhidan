IndexedDB 产品查询效率改善方案

方案1：内存缓存 · 方案2：消除重复构建

🔍 一、问题分析

1.1 当前数据规模

3,822
客户记录
9,201
产品记录
~2.5MB
IndexedDB 总量

1.2 核心瓶颈：重复全量读取

当前 findProductFuzzyMatchFromLS() 每次被调用时，都会从 IndexedDB 执行两次全量读取：

findProductFuzzyMatchFromLS() 被调用 ├─ await getProductsAsync() ← 从 IndexedDB 读取 9,201 条产品 ├─ await getProductPinyinAsync() ← 从 IndexedDB 读取 9,201 条产品（重复！） │ └─ 遍历 9,201 条，重建 {id: {pinyin, pinyin_abbr}} 对象 ├─ 构建 indexDb（9,201 条 map） ← 每次重建！ └─ 执行 pinyinMatch() 匹配

而 matchProductsFromRawList() 对每个原始产品调用一次 findProductFuzzyMatchFromLS()，导致：

matchProductsFromRawList(10个产品) ├─ 循环 10 次： │ ├─ getProductsAsync() × 10 ← 10次全量读取 │ ├─ getProductPinyinAsync() × 10 ← 10次全量读取+重建 │ ├─ 构建 indexDb × 10 ← 10次重建 │ └─ 匹配成功后 getProductsAsync() × 10 ← 又10次全量读取 └─ 合计：30次 IndexedDB 全量读取 + 10次对象重建
🔴 核心问题：10个产品的批量匹配，产生 30 次 IndexedDB 全量读取（每次 9,201 条），以及 10 次拼音对象的重复构建。IndexedDB 的异步读取每次约 5-20ms，30次就是 150-600ms 的纯 I/O 等待，远超匹配算法本身的计算耗时。

1.3 次要瓶颈：getProductPinyinAsync 重复构建

拼音数据已经存储在 product 表的 pinyin 和 pinyin_abbr 字段中，但当前代码仍然：

  1. 全量读取 product 表（9,201条）
  2. 遍历所有记录，提取 pinyin/pinyin_abbr 字段
  3. 构建 {id: {pinyin, pinyin_abbr}} 格式的对象
  4. 在 findProductFuzzyMatchFromLS 中又把该对象拆解回扁平结构

这是"先拆后合再拆"的无效转换：

❌ 当前流程
product 表 → 读取9201条
  → 提取pinyin字段
  → 构建 {id:{pinyin,abbr}}
  → 在findProduct中
  → 又拆解为扁平indexDb
  → {id, name, pinyin, abbr}
✅ 优化后流程
product 表 → 读取9201条（缓存）
  → 直接构建扁平indexDb
  → {id, name, pinyin, abbr}
  → 无中间转换

1.4 性能量化估算

操作单次耗时批量10次占比
IndexedDB 全量读取 (9201条)5-20ms150-600ms60-70%
拼音对象重建 (9201条遍历)2-5ms20-50ms10-15%

⚠️ 关键发现：在批量匹配场景下，I/O 等待（60-70%）远超算法计算（20-25%）。优化 I/O 是投入产出比最高的方向。

⚡ 二、方案1：内存缓存

2.1 设计思路

首次从 IndexedDB 读取数据后，将结果缓存到 JavaScript 内存变量中。后续调用直接从内存读取，不再访问 IndexedDB。当数据发生变更（同步、导入、清空）时，主动使缓存失效。

2.2 缓存层设计

// ===== 内存缓存层 =====

var _productsCache = null;
var _customersCache = null;
var _indexDbCache = null;
var _customerIndexDbCache = null;

async function getProductsCached() {
  if (_productsCache) return _productsCache;
  _productsCache = await getProductsAsync();
  return _productsCache;
}

async function getCustomersCached() {
  if (_customersCache) return _customersCache;
  _customersCache = await getCustomersAsync();
  return _customersCache;
}

async function getProductIndexDbCached() {
  if (_indexDbCache) return _indexDbCache;
  var products = await getProductsCached();
  _indexDbCache = products.filter(function(p) {
    return p.pinyin || p.pinyin_abbr;
  }).map(function(p) {
    return {
      id: p.id,
      name: p.name,
      model: p.model || '',
      spec: p.spec || '',
      pinyin: p.pinyin || '',
      pinyin_abbr: p.pinyin_abbr || ''
    };
  });
  return _indexDbCache;
}

async function getCustomerIndexDbCached() {
  if (_customerIndexDbCache) return _customerIndexDbCache;
  var customers = await getCustomersCached();
  _customerIndexDbCache = customers.filter(function(c) {
    return c.pinyin || c.pinyin_abbr;
  }).map(function(c) {
    return {
      id: c.id,
      name: c.name,
      pinyin: c.pinyin || '',
      pinyin_abbr: c.pinyin_abbr || ''
    };
  });
  return _customerIndexDbCache;
}

function invalidateCache() {
  _productsCache = null;
  _customersCache = null;
  _indexDbCache = null;
  _customerIndexDbCache = null;
}

function invalidateProductCache() {
  _productsCache = null;
  _indexDbCache = null;
}

function invalidateCustomerCache() {
  _customersCache = null;
  _customerIndexDbCache = null;
}

2.3 缓存失效时机

缓存必须在数据变更时主动失效，否则会出现数据不一致：

触发操作失效范围说明
setProductsAsync()产品缓存 + indexDb全量/增量同步后
setCustomersAsync()客户缓存 + indexDb全量/增量同步后
clearAllDataAsync()全部缓存清空数据时
importDataAsync()全部缓存导入数据后
新建产品成功产品缓存 + indexDb添加新产品后
页面初始化不失效（首次加载）首次访问走 IndexedDB

2.5 改造 matchProductsFromRawList

批量匹配时，先加载缓存，再循环匹配，避免循环内重复读取：

❌ 改造前

      combinedName, hasSpec, String(pSpec), modelValue);

        if (String(lsProducts[j].id)
            === String(match.matchId)) {
          matchedProduct = { ... };
          break;
        }
      }
    }
    results.push({ ... });
  }
  return results;
}
✅ 改造后
async function matchProductsFromRawList(rawProducts) {
  // 预加载缓存（只读一次 IndexedDB）
  var products = await getProductsCached();
  var indexDb = await getProductIndexDbCached();

  // 构建 id→product 快速查找表
  var productMap = {};
  products.forEach(function(p) {
    productMap[String(p.id)] = p;
  });

  var results = [];
  for (var i = 0; i < rawProducts.length; i++) {
    var p = rawProducts[i];
    // 直接使用内存中的 indexDb
    var matches = pinyinMatch(combinedName,
      indexDb, { threshold: 0.45 });

    // ... 同名产品区分逻辑（同当前代码）

    // 匹配成功后从 productMap 直接查找
    var matchedProduct = null;
    if (match.matchId) {
      var mp = productMap[String(match.matchId)];
      if (mp) {
        matchedProduct = {
          id: mp.id, name: mp.name,
          code: 'PRD-' + mp.id,
          sku: mp.model || '-',
          spec: mp.spec || ''
        };
      }
    }
    results.push({ ... });
  }

✅ 关键改进：① 循环外预加载缓存，10个产品只读1次 IndexedDB（而非30次）；② 用 productMap 替代线性查找，O(1) 替代 O(N)；③ matchProductsFromRawList 内部直接调用 pinyinMatch()，不再经过 findProductFuzzyMatchFromLS 的间接层。

🔄 三、方案2：消除重复构建

3.1 问题根源

当前 Dexie 表结构中，拼音数据已经作为字段存储在 product/customer 表中：

db.version(1).stores({
  customer: 'id, name, pinyin, pinyin_abbr, update_time',
  product:  'id, name, model, sku, pinyin, pinyin_abbr, update_time',
  sync_status: 'key'
});

但代码仍然维护了独立的 getProductPinyinAsync() 函数，将拼音数据提取为独立对象格式：

// 当前代码：从 product 表读取 → 提取 → 重建对象
async function getProductPinyinAsync() {
  var products = await db.product.toArray();  // 全量读取
  var result = {};
  products.forEach(function(p) {
    result[p.id] = { pinyin: p.pinyin, pinyin_abbr: p.pinyin_abbr };
  });
  return result;  // {id1: {pinyin, pinyin_abbr}, id2: ...}
}

然后在 findProductFuzzyMatchFromLS 中又把该对象拆解回扁平结构：

// 当前代码：从 {id:{pinyin,abbr}} 拆解为扁平 indexDb
var indexDb = products.map(function(p) {
  var py = pp[p.id] || {};  // 从独立对象中查找
  return {
    id: p.id, name: p.name, model: p.model || '', spec: p.spec || '',
    pinyin: py.pinyin || '', pinyin_abbr: py.pinyin_abbr || ''
  };
});

这完全是多余的转换——拼音数据已经在 product 记录的 pinyin/pinyin_abbr 字段中。

3.2 优化方案

直接从 product 表构建 indexDb，跳过 getProductPinyinAsync 中间步骤：

async function getProductIndexDbCached() {
  if (_indexDbCache) return _indexDbCache;
  var products = await getProductsCached();  // 缓存读取
  _indexDbCache = products.filter(function(p) {
    return p.pinyin || p.pinyin_abbr;  // 只保留有拼音的
  }).map(function(p) {
    return {
      id: p.id,
      name: p.name,
      model: p.model || '',
      spec: p.spec || '',
      pinyin: p.pinyin || '',         // 直接从 product 记录读取
      pinyin_abbr: p.pinyin_abbr || '' // 直接从 product 记录读取
    };
  });
  return _indexDbCache;
}

4.2 改造 findProductFuzzyMatchFromLS

async function findProductFuzzyMatchFromLS(name, hasSpec, specValue, modelValue) {
  var products = await getProductsCached();
  var indexDb = await getProductIndexDbCached();

  if (products.length === 0) {
    return { matchId: null, status: 'error', matchType: 'none' };
  }

  var matches = pinyinMatch(name, indexDb, { threshold: 0.45 });
  if (matches.length === 0) {
    return { matchId: null, status: 'error', matchType: 'none' };
  }

  var best = matches[0];

  if (best.score >= 0.9) {
    var sameNameProducts = products.filter(function(p) { return p.name === best.name; });
    if (sameNameProducts.length > 1) {
      var modelMatches = sameNameProducts;
      if (modelValue) {
        var modelExact = sameNameProducts.find(function(p) {
          return p.model && p.model.toLowerCase() === modelValue.toLowerCase();
        });
        if (modelExact) {
          modelMatches = sameNameProducts.filter(function(p) {
            return p.model && p.model.toLowerCase() === modelValue.toLowerCase();
          });
        } else {
          var modelPartial = sameNameProducts.find(function(p) {
            return p.model && (p.model.toLowerCase().indexOf(modelValue.toLowerCase()) !== -1 || modelValue.toLowerCase().indexOf(p.model.toLowerCase()) !== -1);
          });
          if (modelPartial) {
            modelMatches = sameNameProducts.filter(function(p) {
              return p.model && (p.model.toLowerCase().indexOf(modelValue.toLowerCase()) !== -1 || modelValue.toLowerCase().indexOf(p.model.toLowerCase()) !== -1);
            });
          }
        }
      }
      if (modelMatches.length === 1) {
        return { matchId: modelMatches[0].id, status: 'confirmed', matchType: 'sku' };
      }
      if (!isPlaceholder(specValue) && modelMatches.length > 1) {
        var specMatch = modelMatches.find(function(p) {
          return p.spec && p.spec.toLowerCase().indexOf(specValue.toLowerCase()) !== -1;
        });
        if (specMatch) {
          return { matchId: specMatch.id, status: 'confirmed', matchType: 'sku' };
        }
      }
      return { matchId: best.id, status: 'pending', matchType: 'name' };
    }
    return { matchId: best.id, status: 'confirmed', matchType: best.score >= 0.95 ? 'exact' : 'name' };
  }

  if (matches.length === 1 && best.score >= 0.8) {
    return { matchId: best.id, status: 'confirmed', matchType: 'name' };
  }
  if (best.score >= 0.7) {
    return { matchId: best.id, status: 'pending', matchType: 'name' };
  }
  if (matches.length === 1 && best.score >= 0.4) {
    return { matchId: best.id, status: 'pending', matchType: 'name' };
  }
  if (matches.length > 1 && best.score >= 0.4) {
    return { matchId: best.id, status: 'pending', matchType: 'name' };
  }
  return { matchId: null, status: 'error', matchType: 'none' };
}

4.3 改造 matchProductsFromRawList

async function matchProductsFromRawList(rawProducts) {
  var products = await getProductsCached();
  var indexDb = await getProductIndexDbCached();

  var productMap = {};
  products.forEach(function(p) {
    productMap[String(p.id)] = p;
  });

  var results = [];
  for (var i = 0; i < rawProducts.length; i++) {
    var p = rawProducts[i];
    var pName = p.originalName || p.name || '';
    var pModel = p.model || '';
    var pSpec = p.spec || '';
    var combinedParts = [pName];
    if (pModel && !isPlaceholder(pModel) && pName.toLowerCase().indexOf(pModel.toLowerCase()) === -1) {
      combinedParts.push(pModel);
    }
    var combinedName = combinedParts.join(' ');
    var hasSpec = !isPlaceholder(pSpec);

    var matches = pinyinMatch(combinedName, indexDb, { threshold: 0.45 });
    var match = { matchId: null, status: 'error', matchType: 'none' };

    if (matches.length > 0) {
      var best = matches[0];
      if (best.score >= 0.9) {
        var sameNameProducts = products.filter(function(pr) { return pr.name === best.name; });
        if (sameNameProducts.length > 1) {
          var modelMatches = sameNameProducts;
          var modelValue = isPlaceholder(pModel) ? '' : pModel;
          if (modelValue) {
            var modelExact = sameNameProducts.find(function(pr) {
              return pr.model && pr.model.toLowerCase() === modelValue.toLowerCase();
            });
            if (modelExact) {
              modelMatches = sameNameProducts.filter(function(pr) {
                return pr.model && pr.model.toLowerCase() === modelValue.toLowerCase();
              });
            } else {
              var modelPartial = sameNameProducts.find(function(pr) {
                return pr.model && (pr.model.toLowerCase().indexOf(modelValue.toLowerCase()) !== -1 || modelValue.toLowerCase().indexOf(pr.model.toLowerCase()) !== -1);
              });
              if (modelPartial) {
                modelMatches = sameNameProducts.filter(function(pr) {
                  return pr.model && (pr.model.toLowerCase().indexOf(modelValue.toLowerCase()) !== -1 || modelValue.toLowerCase().indexOf(pr.model.toLowerCase()) !== -1);
                });
              }
            }
          }
          if (modelMatches.length === 1) {
            match = { matchId: modelMatches[0].id, status: 'confirmed', matchType: 'sku' };
          } else if (!isPlaceholder(pSpec) && modelMatches.length > 1) {
            var specMatch = modelMatches.find(function(pr) {
              return pr.spec && pr.spec.toLowerCase().indexOf(pSpec.toLowerCase()) !== -1;
            });
            if (specMatch) {
              match = { matchId: specMatch.id, status: 'confirmed', matchType: 'sku' };
            } else {
              match = { matchId: best.id, status: 'pending', matchType: 'name' };
            }
          } else {
            match = { matchId: best.id, status: 'pending', matchType: 'name' };
          }
        } else {
          match = { matchId: best.id, status: 'confirmed', matchType: best.score >= 0.95 ? 'exact' : 'name' };
        }
      } else if (matches.length === 1 && best.score >= 0.8) {
        match = { matchId: best.id, status: 'confirmed', matchType: 'name' };
      } else if (best.score >= 0.7) {
        match = { matchId: best.id, status: 'pending', matchType: 'name' };
      } else if (best.score >= 0.4) {
        match = { matchId: best.id, status: 'pending', matchType: 'name' };
      }
    }

    var matchedProduct = null;
    if (match.matchId) {
      var mp = productMap[String(match.matchId)];
      if (mp) {
        matchedProduct = {
          id: mp.id, name: mp.name,
          code: 'PRD-' + mp.id,
          sku: mp.model || '-',
          spec: mp.spec || ''
        };
      }
    }

    results.push({
      originalName: pName,
      model: pModel,
      searchName: combinedName,
      originalQty: p.qty ? (String(p.qty) + (p.unit || '')) : '',
      originalPrice: p.price ? ('¥' + p.price) : '',
      originalSpec: String(pSpec),
      matchedId: match.matchId,
      matchedName: matchedProduct ? matchedProduct.name : '',
      matchedCode: matchedProduct ? matchedProduct.code : '',
      matchedSku: matchedProduct ? matchedProduct.sku : '',
      matchedSpec: matchedProduct ? matchedProduct.spec : '',
      matchType: match.matchType,
      status: match.status,
      qty: p.qty ? (String(p.qty) + (p.unit || '')) : '',
      price: p.price ? ('¥' + p.price) : '',
      spec: pSpec,
      note: p.note || ''
    });
  }
  return results;
}

⚠️ 六、风险与注意事项

6.1 内存占用

缓存 9,201 条产品 + 3,822 条客户到内存，约增加 3-5MB 内存占用。对于现代浏览器来说完全可接受。

6.2 数据一致性

缓存失效机制确保数据一致性。但需注意：

  • 多标签页场景：如果用户在标签页A同步数据，标签页B的缓存不会自动失效
  • 解决方案：监听 storage 事件或使用 BroadcastChannel 通知其他标签页刷新缓存

6.3 兼容性

保留 getProductPinyinAsync/getCustomerPinyinAsync 的导出，标记为 deprecated，确保 get_cus_pro.html 等外部调用方不受影响。
