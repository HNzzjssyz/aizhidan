1项目目标与定位

核心定位：AI驱动的智能制单工作台 —— 将多源异构订单需求自动转化为标准制单，覆盖从"客户表达需求"到"生成标准订单"的完整链路。

AI智能制单系统解决的根本问题是：客户表达的产品需求与业务系统中的标准产品名称之间存在语义鸿沟。这种鸿沟体现在三个层面：

🔊

语音转文字偏差

语音识别产生同音字、错别字，"华美"→"华梅"，"工控"→"工空"

📝

参数描述型输入

客户用功能参数描述产品，"护目镜 防冲击 防喷溅 聚碳酸酯"而非标准品名

🔄

命名习惯差异

客户说"长雨衣"，系统里叫"长款连体雨衣"；客户说"线手套"，系统里有"线手套 分指 棉纱"

📋

多源格式混乱

微信文字、Excel截图、电话语音、邮件附件，每种渠道格式各异

项目目标：构建一套双路并行的智能匹配算法，同时覆盖"语音同音字"和"参数描述型"两大类匹配场景，让销售人员从耗时的手动查找中解放出来。

2核心场景一：销售语音下单

场景描述

销售人员通过电话或语音与客户沟通，客户口述需求，销售人员需要将语音内容转化为标准订单。语音经Coze智能体识别后返回结构化JSON，系统自动匹配客户和产品。

典型流程

客户语音表达需求 → Coze智能体语音识别 → 结构化JSON输出 → AI自动匹配客户+产品 → 销售确认订单

核心挑战：语音识别偏差

语音转文字天然存在同音字、错别字问题，这是拼音匹配引擎的核心战场：

语音
同音不同字：客户说"华美"，语音识别为"华梅" → 拼音匹配自动关联到系统中的"华美"客户
语音
错别字：客户说"工控"，识别为"工空" → 拼音全拼相似度兜底匹配
语音
方言口音："zh/z"不分、"l/n"混淆 → 拼音模糊匹配覆盖常见方言差异

匹配算法选择

语音下单场景中，客户通常说出的是标准品名或简称（如"线手套""耐酸碱手套"），与系统中的产品名称高度重叠，拼音匹配引擎即可高效覆盖。当客户用功能参数描述时（见场景二），则需要分词关键词匹配引擎补充。

场景一算法策略：拼音匹配为主（权重55%），分词关键词匹配为辅（权重45%）。拼音引擎解决同音字和错别字，分词引擎兜底参数描述型输入。

3核心场景二：甲方询价制单

场景描述

甲方（采购方）发出询价需求，通常以文字形式提供详细的产品参数描述。乙方（销售方）需要根据这些参数描述，在自有产品库中找到对应产品并制单报价。这类输入的特点是：用功能参数描述产品，而非使用标准品名。

典型流程

甲方发送询价需求 → 系统分词提取关键词 → 关键词倒排索引检索 → 质量加权评分排序 → 销售确认匹配结果

核心挑战：参数描述型输入

甲方询价时，输入内容是产品的功能参数描述，与系统中的标准品名存在显著语义鸿沟：

文字
护目镜用例：输入"护目镜 防冲击 防喷溅 防粉尘 防紫外线 聚碳酸酯 透明" → 目标产品"3M护目镜防冲击防喷溅"、"3M护目镜防粉尘防紫外线"等。拼音匹配得分仅0.32，分词匹配可提升至0.48-0.50
文字
雨衣用例：输入"雨衣 防水牛津面料 长款连体雨衣 银灰色反光条" → 目标产品"长雨衣"。"长款连体雨衣"与"长雨衣"字符重叠率0.67，分词匹配可命中
文字
耐酸碱手套用例：输入"耐酸碱手套 长350MM 80-103g 乳胶" → 需区分"耐酸碱手套"与普通"乳胶手套"，质量加权评分避免通用词干扰

为什么拼音匹配不够？

参数描述型输入的拼音匹配存在三个结构性弱点：

弱点 原因 影响
拼音序列有序 vs 参数无序 拼音匹配依赖序列对齐，但参数描述的顺序与品名顺序不同 全拼相似度大幅下降
长度差异悬殊 输入"护目镜 防冲击 防喷溅..."远长于品名"3M护目镜" 长度相似度拉低总分
词袋粒度过细 拼音词袋以字为粒度，"防冲击"拆为"fang""chong""ji"，无法匹配"防冲击" 词袋相似度失效
场景二算法策略：分词关键词匹配为主（权重45%），拼音匹配为辅（权重55%表面权重高，但参数描述型输入的拼音得分本身很低，实际由分词路径主导命中）。分词引擎通过关键词倒排索引+质量加权评分，精准命中参数描述型产品。

4.1 拼音匹配引擎

拼音匹配引擎是系统的基础匹配能力，擅长处理同音字、错别字、方言口音等语音识别偏差场景。

四维加权评分

全拼相似度
35%
首字母相似度
25%
词袋余弦相似度
30%
长度相似度
10%

适用场景

  • 同音不同字："华美"匹配"华梅" —— 全拼相同，相似度满分
  • 错别字纠正："工空"匹配"工控" —— 全拼相似度兜底
  • 方言口音容错："zh/z"不分、"l/n"混淆 —— 模糊匹配覆盖
  • 简称/缩写识别："晨光A4"匹配"晨光文具A4复印纸" —— 首字母+词袋双重匹配

4.2 分词关键词匹配引擎

分词关键词匹配引擎是系统的增强匹配能力，专为参数描述型输入场景设计，解决拼音匹配在"输入内容是功能参数而非标准品名"时的失效问题。

处理流程

中文分词 → 关键词倒排索引 → 候选检索 → 质量加权评分

中文分词策略

  • 空格/标点分割：优先按空格和标点符号拆分，保留语义完整性
  • 贪心最长匹配：对超过4字的纯中文串，使用劳保行业词典进行贪心最长匹配拆分
  • 行业词典：维护劳保行业常见2字后缀、2字前缀、3字常见词词典
  • 兜底策略：无法匹配词典词时，按2字粒度切分

关键词倒排索引

为产品库中每个产品提取关键词（品名+型号+规格分词去重），构建 keyword → [productIndex1, productIndex2, ...] 的倒排索引，实现O(1)关键词检索。

质量加权评分（keywordMatchScore）

对每个查询token，在产品关键词中寻找最佳匹配质量，并按token权重加权求和：

匹配类型 质量计算 说明
精确匹配 1.0 查询token与产品关键词完全一致
子串匹配 短词长度 / 长词长度 按长度比折扣，避免短词误匹配长词
字符重叠匹配 overlapRatio × minLen / maxLen 仅纯中文token生效，阈值0.6

Token权重体系

纯中文 ≥3字
1.5
纯中文 2字
1.0
非纯中文
0.5

否定词检测

字符重叠匹配内置否定词检测机制，当两端否定状态不同时（如"银灰色反光条"↔"无反光条"），charOverlapRatio返回0，避免语义相反的产品误匹配。否定词列表：无、非、不、未。

4.3 双路融合策略

融合公式：fusedScore = pinyinScore × 0.55 + kwScore × 0.45

双路融合的设计原则：

  • 拼音为主、分词为辅：55:45的权重分配确保语音识别偏差场景（拼音擅长的领域）仍由拼音引擎主导
  • 分词兜底参数描述：当拼音得分因长度差异、序列错位而偏低时，分词路径的关键词命中可显著提升总分
  • 候选合并去重：两路引擎分别检索候选产品，合并后统一评分排序，避免遗漏
  • 全链路覆盖：主匹配窗口和重新匹配弹窗均采用双路融合，确保体验一致

用例验证

用例 纯拼音得分 双路融合得分 提升
护目镜（参数描述型） 0.32 0.48-0.50 +50%
雨衣（字符重叠型） 未命中 命中（charOverlap 0.67） 从0到1
耐酸碱手套（通用词干扰型） 误匹配 质量加权精准排序 精准度显著提升

5核心价值总结

🎯

双场景全覆盖

语音下单（同音字/错别字）+ 询价制单（参数描述型），一套算法两种场景

⚡

双路互补增强

拼音引擎解决语音偏差，分词引擎解决语义鸿沟，融合后命中率显著提升

🛡️

质量加权防误匹配

Token权重+匹配质量+否定词检测三重保障，避免通用词和语义相反产品干扰

🔧

行业词典可扩展

劳保行业词典可按行业定制，贪心最长匹配策略通用可复用

核心价值：让销售和业务人员从"查找客户和产品占60%时间"的低效状态中解放出来，AI自动匹配+人工确认的模式，兼顾效率与准确度。

算法

字符重叠匹配（charOverlapRatio）

新增字符重叠率计算，解决"长款连体雨衣"↔"长雨衣"等中间隔字符的匹配问题，阈值0.6

算法

否定词检测

字符重叠匹配内置否定词检测（无/非/不/未），"银灰色反光条"↔"无反光条"不再误匹配

算法

质量加权评分替代hit/miss计数

解决三种误匹配：单字符子串（"m"匹配"350mm"）、数字字符重叠（"103g"↔"100只"）、通用词权重过高（"手套"）

修复

分词标签拼接丢失空格

join('') → join(' ')，修复"线手套 分指 棉纱 原白色"变成一个巨型token的问题

算法

重新匹配窗口双路融合

fuzzyMatchProducts改造为双路融合，确保主窗口和重新匹配弹窗体验一致

界面

重新匹配弹窗原始内容颜色加深

原始内容从灰色改为深色加粗显示，方便用户比对原始输入与匹配结果
