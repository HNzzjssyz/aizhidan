★ 5 句话讲清核心

  • 加载：用 Coze 官方 CDN（lf-cdn.coze.cn） 1 行 <script>，全局对象 CozeWebSDK.WebChatClient 即开即用
  • 鉴权主轨：前端永不接触 PAT，每次启动调自家后端 /system/bot/token.xt 拿一个短期 token
  • 鉴权辅轨：高级用户可手动粘贴 PAT（存 IndexedDB），用于调试个人智能体
  • token 刷新：实现 onRefreshToken 回调，过期时 SDK 自动续期
  • 核心代码量：3 个函数 + 30 行（fetchCozeToken / initCozeSDK / onRefreshToken）即可完成全链路

【核心 1】加载方式：CDN Script 1 行引入

1.1 选择 CDN Script 而不是 NPM 打包

对比项CDN Script 引入（✅本项目用）NPM 打包（webpack/vite）
接入成本1 行 script安装依赖 + 配置构建
首屏体积不占主 bundle，浏览器并行下载增加主 bundle 体积
版本升级改 URL 中的版本号即可升级 npm 依赖 + 重新构建
多页面项目所有页面共享浏览器缓存每个 bundle 都要打一份
国内访问用 lf-cdn.coze.cn，速度快不影响

结论：本项目是"嵌入到现有 CRM 系统"的工具型页面，用 CDN Script 引入最划算。

1.2 完整加载代码（[index.html L8](file:///Users/guorui/同步空间/20021218/临时开发/智能制单/拼音试验/dexiedb/index.html#L8)）

URL 拆解：

  • lf-cdn.coze.cn：字节跳动 CDN，国内访问稳定

脚本加载后，浏览器挂一个 CozeWebSDK 全局变量。所有 API 从这里出：

// 常用方法

client.hideChatBot();      // 隐藏
client.destroy();          // 销毁（切换智能体时必须调用）

1.4 加载时机检测（防未加载就调用）

if (typeof CozeWebSDK === 'undefined') {
  throw new Error('Coze SDK 未加载，请检查网络后刷新页面');

坑：如果 CDN 加载慢或失败，直接调用 new CozeWebSDK.WebChatClient(...) 会报 CozeWebSDK is undefined。在 initCozeSDK 开头加上面这层保护。

【核心 2】鉴权方式：双轨制

2.1 本项目使用的双轨制鉴权

本系统采用 "后端代理发 Token" + "用户可手动覆盖 PAT" 的双轨方案：

轨道触发条件Token 来源存哪适用场景
主轨：后端代理 用户没有配置自定义智能体 后端 /system/bot/token.xt 动态生成 仅在 JS 内存 99% 场景（生产）
辅轨：用户 PAT 用户在配置面板添加并启用了自定义智能体 用户从 Coze 平台手动粘贴 IndexedDB（加密可选） 个人/调试/演示

【核心 3】后端代理发 Token 的实现细节

3.1 为什么不直接把 PAT 写前端？

致命风险：Coze PAT（Personal Access Token）相当于 Coze 平台的 超级用户凭证，拿到后可以：

  • 调用该账号下所有智能体
  • 读取所有知识库
  • 消耗所有付费额度

如果写死在 JS 里，任何用户打开 DevTools 都能看到，等于把钥匙挂在门上。

3.2 前端调用：fetchCozeToken()（[L1786-1797](file:///Users/guorui/同步空间/20021218/临时开发/智能制单/拼音试验/dexiedb/index.html#L1786-L1797)）

var API_BASE = '/system';

async function fetchCozeToken() {
  var response = await fetch(API_BASE + '/bot/token.xt', {
    method: 'GET',
    credentials: 'include',   // 携带 CRM 自身的登录态 cookie
    headers: { 'Content-Type': 'application/json' }
  });
  var data = await response.json();
  if (data.ok !== 1 || !data.accessToken) {
    throw new Error(data.msg || '获取 Coze 令牌失败');
  }
  return data.accessToken;   // ← 短期 token，仅本次有效
}

3.3 后端 /system/bot/token.xt 的内部实现（伪代码）

// 伪代码：项目后端实现示意（不暴露真实凭证）
async function handleTokenRequest(req, res) {
  // ① 校验调用方身份（CRM 自身的 session/cookie）
  var session = checkSession(req);
  if (!session) return res.json({ ok: 0, msg: '未登录' });

  // ② 检查是否已有未过期的 token（缓存复用）
  var cached = getCachedToken(session.userId);
  if (cached && cached.expiresAt > Date.now() + 60000) {
    return res.json({ ok: 1, accessToken: cached.token });
  }

  // ③ 调 Coze 鉴权服务，生成短期 token
  //    关键：服务端的 PAT 凭证从环境变量读，绝不出现在请求/响应中
  var cozeRes = await fetch('https://api.coze.cn/v1/oauth/token', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'Authorization': 'Bearer ' + process.env.COZE_SERVICE_PAT  // ← 服务端凭证
    },
    body: JSON.stringify({
      grant_type: 'client_credentials',
      duration_seconds: 3600   // 1 小时有效期
    })
  });
  var cozeData = await cozeRes.json();

  // ④ 缓存到 Redis（按 user 隔离）
  saveCachedToken(session.userId, cozeData.access_token, cozeData.expires_in);

  // ⑤ 只返回给浏览器短期 token
  return res.json({ ok: 1, accessToken: cozeData.access_token });
}

3.4 服务端凭证的安全保护

措施说明
环境变量存储COZE_SERVICE_PAT 存 .env，不进 git
Redis 缓存避免每次都调 Coze 鉴权（限流友好）
短期 token返回给浏览器的 token 仅 1 小时有效
Session 校验未登录的请求直接拒绝
服务端 PAT 永不下发浏览器永远拿不到真正的"主人钥匙"

关键设计：前端拿到的是"客房钥匙"（短期、有限权限、丢了无所谓），真正的"主人钥匙"（服务端 PAT）永远锁在保险箱里（服务端环境变量）。

【核心 5】双轨制仲裁逻辑：何时用后端？何时用 PAT？

5.1 仲裁代码：loadActiveAgent()

// 从 IndexedDB 读用户配置的"激活"智能体
async function loadActiveAgent() {
  var all = await AgentConfig.getAll();   // 读 IndexedDB
  var active = all.find(function (a) { return a.active === true; });
  return active || null;   // null = 没配置，走后端代理
}

5.2 仲裁决策表

条件结果Token 来源
没配置任何智能体 OR 没有"激活"的 走主轨 fetch('/system/bot/token.xt')
配置了智能体但 PAT 为空 走主轨 fetch('/system/bot/token.xt')
配置了智能体且 PAT 非空 走辅轨 用 IndexedDB 中的 PAT
辅轨的 PAT 也失效（onRefreshToken 回调） 仍走辅轨 返回原 PAT（用户自行去 Coze 平台续期）

5.3 切换智能体 → 触发重新初始化

function selectAgent(id) {
  AgentConfig.setActive(id).then(function () {
    return loadActiveAgent();
  }).then(function (agent) {
    renderAgentConfigList();
    showToast('已切换智能体，正在重新连接...');
    initCozeSDK();   // ← 销毁旧 client，重新走仲裁
  });
}

【核心 6】为什么这样设计？三平衡考量

6.1 三个核心目标

目标主轨如何满足辅轨如何满足
安全 PAT 不出服务端，浏览器拿到的 token 短期+可撤销 PAT 由用户自己保管，泄露责任自担
灵活性 统一管理，多用户共享同一智能体 个人可挂自己的 Bot 调试，不影响主流程
降级 辅轨可独立使用，即使后端宕机也能跑 主轨可独立使用，即使没配 PAT 也能跑

6.2 与"全后端代理"和"全前端 PAT"方案的对比

方案安全灵活降级实现成本本项目选择
全后端代理（无 PAT 覆盖） ✅✅✅ ❌ ❌（后端宕就全废） 低 —
全前端 PAT（无后端代理） ❌ ✅✅✅ ✅ 低 —
双轨制（本项目） ✅✅ ✅✅ ✅✅ 中 ✅

6.3 适用边界

本系统作为内部业务系统，用户数有限、需要快速试错各种 Bot，双轨制收益最大。

如果做对外 SaaS，建议只用主轨（更安全），辅轨对管理员开放即可。

附录 A：initCozeSDK 完整流程

var cozeClient = null;
var cozeAccessToken = null;

async function initCozeSDK() {
  // ① 拉取当前激活的智能体配置
  var agent = await loadActiveAgent();
  var useBotId = (agent && agent.bot_id) ? agent.bot_id : '7638933573109792777';
  var useToken = (agent && agent.token) ? agent.token : await fetchCozeToken();
  cozeAccessToken = useToken;

  if (typeof CozeWebSDK === 'undefined') {
    throw new Error('Coze SDK 未加载，请刷新页面');
  }

  // ② 销毁旧实例（重要！否则会重复挂载）
  if (cozeClient && typeof cozeClient.destroy === 'function') {
    cozeClient.destroy();
  }

  // ③ 创建新客户端
  cozeClient = new CozeWebSDK.WebChatClient({
    config: { bot_id: useBotId },
    auth: {
      type: 'token',
      token: useToken,
      onRefreshToken: async function () {
        if (agent && agent.token) return agent.token;
        cozeAccessToken = await fetchCozeToken();
        return cozeAccessToken;
      }
    },
    ui: {
      base: { lang: 'zh-CN', zIndex: 50 },
      asstBtn: { isNeed: true },
      chatBot: {
        title: agent?.name || '智能制单助手',
        uploadable: true,
        width: 460
      },
      header: { isShow: true, isNeedClose: false }
    }
  });

  // ④ 显示聊天窗口
  setTimeout(function () {
    if (cozeClient && typeof cozeClient.showChatBot === 'function') {
      cozeClient.showChatBot();
    }
  }, 500);
}

附录 C：图片粘贴转发（增强体验）

用户在网页任意位置 Ctrl+V 粘贴图片时，自动转发到 Coze SDK 上传框：

document.addEventListener('paste', function (e) {
  // 1. 检测是否包含图片
  var hasImage = Array.from(e.clipboardData.items).some(function (it) {
    return it.kind === 'file' && it.type.indexOf('image/') === 0;
  });
  if (!hasImage) return;

  // 2. 不要重复（如果光标在 SDK 输入区，让 SDK 自己处理）
  if (isInCozeSDKArea(e.target)) return;

  // 3. 把文件喂给 SDK 的隐藏 file input
  e.preventDefault();
  var fileInput = document.querySelector('input.coze-chat-sdk-semi-upload-hidden-input');
  if (fileInput) {
    var dt = new DataTransfer();
    Array.from(e.clipboardData.files).forEach(function (f) { dt.items.add(f); });
    fileInput.files = dt.files;
    fileInput.dispatchEvent(new Event('change', { bubbles: true }));
  }
}, true);  // 捕获阶段

附录 D：常见坑与避雷清单

坑症状解决方案
PAT 硬编码在 JSDevTools 一打开就泄露走后端代理，前端永不接触 PAT
不 destroy 直接 new浮窗重复挂载、事件多次触发init 开头 if (cozeClient) cozeClient.destroy();
Token 过期没处理对话几分钟后 401实现 onRefreshToken
zIndex 设太大Coze 浮窗盖住业务弹窗Coze 设 50，业务弹窗 1000+
CDN 加载慢页面卡白几秒加 async/defer，初始化失败有提示
SDK 未加载就调用CozeWebSDK is undefined用 typeof CozeWebSDK === 'undefined' 检测
