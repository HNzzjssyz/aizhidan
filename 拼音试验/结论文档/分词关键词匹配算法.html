1. 背景与动机

原有拼音匹配算法在"品名精确匹配"场景下表现优秀，但在参数描述型输入场景下存在结构性缺陷：

典型失败场景
输入：护目镜 防冲击、防喷溅、防粉尘、防紫外线 聚碳酸酯 透明
目标：3M 1621AF PC 防雾/透明/防化/防冲击/护目镜（眼罩）
拼音匹配得分：0.32（低于0.45阈值，无法匹配）

三个根因：

缺陷原因影响
有序串 vs 无序集 Levenshtein/首字母匹配依赖顺序一致性 参数顺序不同导致得分暴降
子集 vs 全集 输入是核心参数，产品名含品牌/型号等额外信息 长度差异是固有特征，无法消除
拼音粒度过细 单字拼音token导致跨词误匹配，品牌/型号稀释余弦分母 wordBag维度也受影响
解决方案：在拼音匹配基础上，新增中文分词关键词匹配作为并行查询路径，两者加权融合输出最终得分。关键词匹配天然支持无序集合运算和子集匹配语义。
2. 整体架构 
输入文本
  │
  ├──→ 拼音匹配路径（原有）
  │     生成拼音 → 拼音倒排索引 → 候选集 → 四维评分 → pinyinScore
  │
  ├──→ 关键词匹配路径（新增）
  │     中文分词 → 关键词倒排索引 → 候选集 → 质量加权评分 → kwScore
  │
  └──→ 双路融合
        fusedScore = pinyinScore × 0.55 + kwScore × 0.45
        按融合得分排序，沿用原有阈值分级策略
fusedScore = pinyinScore × 55% + kwScore × 45%
权重设计理由：拼音匹配在品名精确匹配场景下仍然是最可靠的路径，因此保持略高权重。关键词匹配在参数描述型场景下优势明显，45%权重足以将原本0.32的拼音得分拉升至0.48以上（超过0.45阈值）。
3. 三种匹配模式

原混合匹配模式（拼音+关键词双路融合）已拆分为三种独立可选模式，用户可在产品选择界面通过切换开关实时切换：

模式匹配路径适用场景默认
分词 (keyword) 中文分词 → 关键词倒排索引 → keywordMatchScore评分 参数描述型输入、多关键字组合查询 默认
拼音 (pinyin) 拼音生成 → 拼音倒排索引 → 四维评分 精确品名匹配、语音输入同音字纠错 —
混合 (mixed) 拼音+关键词候选合并 → 拼音评分+关键词评分 → 55%+45%融合 通用场景，兼顾全面性 —
3.1 调度逻辑 
var _matchMode = 'keyword';  // 默认分词模式

async function fuzzyMatchProducts(name, limit, modelValue) {
  if (_matchMode === 'pinyin')  return await fuzzyMatchByPinyin(name, limit);
  if (_matchMode === 'keyword')  return await fuzzyMatchByKeyword(name, limit);
  return await fuzzyMatchByMixed(name, limit);
}
3.2 UI切换控件

产品选择浮窗（重新匹配/搜索产品）顶部显示匹配模式切换按钮组，分词模式下搜索框下方额外显示"可用空格分词"提示。切换模式后自动触发重新搜索。

默认分词模式的设计理由：实际业务中，AI生成的订单产品名多为参数描述型（如"护目镜 防冲击 防喷溅"），分词匹配在此场景下命中率最高。用户遇到分词匹配不理想时，可一键切换到拼音或混合模式。
3.3 关键字高亮

在分词/混合模式下，产品候选列表中的产品名会高亮显示匹配的分词关键字，帮助用户快速定位匹配依据：

// 高亮函数：在已转义HTML中，按关键词（长词优先）正则替换
function highlightKeywords(html, tokens) {
  var sorted = tokens.slice().sort(function(a, b) { return b.length - a.length; });
  for (var ti = 0; ti < sorted.length; ti++) {
    var escaped = sorted[ti].replace(/[.*+?^${}()|[\]\\]/g, '\\$&');
    html = html.replace(new RegExp(escaped, 'gi'), '<span class="kw-highlight">$&</span>');
  }
  return html;
}

高亮样式：.kw-highlight { background:#fef08a; color:#92400e; border-radius:2px; }，黄色背景+深棕色文字，醒目但不干扰阅读。拼音模式下不高亮。

4. 中文分词策略

分词是关键词匹配的基础，采用空格/标点分割 + 长词智能拆分两阶段策略：

4.1 第一阶段：空格/标点分割

按标点符号（、，,；;：:（）()/\｜·—–）和空格分割，过滤量词和纯数字。

输入分词结果
护目镜 防冲击、防喷溅、防粉尘、防紫外线 聚碳酸酯 透明["护目镜","防冲击","防喷溅","防粉尘","防紫外线","聚碳酸酯","透明"]
线手套 分指 棉纱 原白色["线手套","分指","棉纱","原白色"]
4.2 第二阶段：长词智能拆分

当无空格输入（如语音识别结果）导致出现超长中文token（>4字）时，使用贪心最长匹配策略拆分：

贪心最长匹配算法
1. 维护劳保行业常见词词典（手套、雨衣、防冲击、防紫外线等），按词长降序排列
2. 在长词中找最长匹配词，拆出前后部分递归处理
3. 无词典匹配时退化为2字切分
输入（无空格）拆分结果
线手套分指棉纱原白色["手套","分指棉纱","原白色"]（"分指棉纱"通过charOverlap补偿）
护目镜防冲击防喷溅防粉尘防紫外线聚碳酸酯透明["护目镜","防冲击","防喷溅","防粉尘","防紫外线","聚碳酸酯","透明"]
雨衣防水牛津面料长款连体雨衣银灰色反光条["雨衣防水","牛津面料","长款","连体雨衣","银灰色","反光条"]
分词标签拼接修复：重新匹配窗口中，分词标签的 join('') 会吃掉空格，导致有空格输入被降级为无空格。已修复为 join(' ')，保留空格分隔。
5. 关键词倒排索引

为加速候选检索，构建关键词倒排索引（内存缓存，首次匹配时自动构建）：

索引结构：keyword → [productIndex1, productIndex2, ...]

示例：
  "手套" → [0, 3, 5, 7, 12, ...]
  "防冲击" → [0, 1, 5, ...]
  "透明" → [0, 2, ...]

候选检索策略：

匹配类型规则示例
精确匹配 查询token === 索引key "防冲击" ↔ "防冲击"
子串匹配 索引key包含查询token，或反之 "防化" ↔ "防化服"、"手套" ↔ "线手套"
字符重叠 纯中文token间字符重叠率≥60% "长款连体雨衣" ↔ "长雨衣"

查询token命中任意产品的次数 ≥ minOverlap 时，该产品进入候选集。minOverlap = queryTokens.length ≤ 2 ? 1 : ceil(length × 0.3)

6. 质量加权评分（keywordMatchScore）

关键词匹配得分采用质量加权而非简单的hit/miss计数。每个查询token独立计算匹配质量，再按权重汇总：

kwScore = Σ(qualityi × weighti) / Σ(weighti)
6.1 Token权重
Token类型条件权重设计理由
纯中文长词 纯中文且≥3字 1.5 "耐酸碱"是核心区分词，权重最高
纯中文短词 纯中文且2字 1.0 "手套"是通用词，权重适中
非纯中文 含数字/字母 0.5 "长350mm"、"103g"匹配意义低
6.2 匹配质量计算
匹配类型质量公式示例quality
精确匹配 1.0 "耐酸碱" = "耐酸碱" 1.0
查询⊂目标 qt.length / rk.length "乳胶" ⊂ "乳胶9寸6.2g" 0.29
目标⊂查询 rk.length / qt.length "m" ⊂ "长350mm" 0.17
字符重叠 overlapRatio × minLen/maxLen "长款连体雨衣" ↔ "长雨衣" 0.50
不匹配 0 "耐酸碱" ↔ "医用检查" 0
6.3 关键防护机制
字符重叠仅对纯中文token生效
数字/字母的字符重叠无语义意义。例如"103g"与"100只"共享字符{1,0}，重叠率0.67，但这是无意义匹配。
修复：charOverlapRatio仅在两端都是纯中文时才启用。
否定词检测
"银灰色反光条"与"无反光条"虽然字符重叠75%，但"无"是否定前缀，语义相反。
修复：检测否定前缀（无/非/不/未），两端否定状态不同时charOverlapRatio直接返回0。
子串匹配按长度比折扣
旧算法中"m"匹配"长350mm"算一次完整hit（1.0），质量极低。
修复：子串匹配质量 = 短词长度 / 长词长度，"m"匹配"长350mm"质量仅0.17。

8. 缓存与性能

关键词匹配相关缓存均为内存缓存，首次匹配时自动构建，产品数据变更时自动失效：

缓存变量内容构建时机失效时机
_productKeywordCache所有产品的关键词列表首次调用getProductKeywordCacheinvalidateCache / invalidateProductCache
_keywordInvertedIndex关键词→产品索引的倒排表首次调用getKeywordInvertedIndexCachedinvalidateCache / invalidateProductCache
性能影响：关键词匹配为纯内存计算，无IndexedDB读写，构建索引约10-30ms（取决于产品数量）。每次匹配额外开销约5-15ms，整体性能约为原拼音匹配的1.5-2倍，在可接受范围内。
无需预存储：与拼音方案不同，关键词分词直接从产品的name/model/spec字段实时计算，不需要在get_cus_pro页面额外"生成分词"或存储到IndexedDB。
9. 拼音 vs 关键词 vs 混合：适用场景对比
场景拼音匹配关键词匹配混合匹配推荐模式
精确品名匹配 强项 强项 强项 拼音/混合
参数子集匹配 弱项 强项 强项 分词/混合
语音输入同音字错误 强项 弱项 强项 拼音/混合
品牌名模糊搜索 可以 部分 可以 拼音/混合
无空格连续输入 部分 智能拆分 智能拆分 分词/混合
否定语义区分 无法区分 否定词检测 否定词检测 分词/混合
核心设计原则：三种模式不是替代关系，而是互补关系。默认使用分词模式（命中率最高），用户可一键切换到拼音或混合模式应对特殊场景。混合模式兼顾全面性但计算量最大，分词/拼音模式更轻量。
