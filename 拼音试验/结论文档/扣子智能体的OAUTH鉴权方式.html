一、概述：两种鉴权模式

本系统的 Coze 智能体支持两种鉴权模式，在 initCozeSDK() 中通过 Agent 配置自动选择：

PAT 模式（agent.token）

  • Token 直接写在前端 IndexedDB 中
  • F12 可见，存在泄露风险
  • 无需后端参与，配置简单
  • Token 长期有效，不会自动过期
  • 适合开发调试或单人使用

OAuth 模式（本文档）

  • 密钥（RT）只存在后端，前端不可见
  • 前端只拿到临时 JWT（access_token）
  • JWT 有过期时间，SDK 自动续期
  • 支持多用户、多会话隔离
  • 适合生产环境部署

选择逻辑（[index.html 1803-1805 行](file:///Users/guorui/同步空间/20021218/临时开发/智能制单/拼音试验/dexiedb/index.html#L1803-L1805)）：

var agent = await loadActiveAgent();
var useBotId = (agent && agent.bot_id) ? agent.bot_id : '7638933573109792777';
var useToken = (agent && agent.token) ? agent.token : await fetchCozeToken();
//                                         ↑ 有 PAT 用 PAT          ↑ 无 PAT 走 OAuth
📘 核心判断

如果 AgentConfig 中 agent.token 有值 → PAT 模式；为空 → OAuth 模式（本文档内容）。

2.1 各阶段职责

阶段执行方动作持有密钥
1. 触发 前端 用户点击"启动智能体"按钮，调用 initCozeSDK() 无
2. 请求令牌 前端 fetch('/system/bot/token.xt') 向后端要 token 无
3. 签发 JWT 业务后端 后端用持有的 RT（密钥）向 Coze OAuth API 请求 access_token RT（密钥）
4. 返回 Coze 平台 签发 JWT 格式的 access_token，返回给业务后端 —
5. 透传 业务后端 将 access_token 包装成 {ok:1, accessToken:"xxx"} 返回前端 —
6. 注入 SDK 前端 将 access_token 传入 CozeWebSDK.WebChatClient 的 auth.token 临时 JWT
7. 续期 SDK → 前端 → 后端 JWT 过期时，SDK 调 onRefreshToken 回调，重新走步骤 2-5 无

2.2 为什么需要后端代理

⚠️ 如果把 RT 直接放在前端
  • F12 → Sources / Network 中密钥完全暴露
  • 任何人打开开发者工具就能拿到 RT
  • RT 长期有效，泄露后等于完全失控
  • 无法做会话隔离、无法按用户限流
✅ 后端代理的好处
  • RT 只存在后端代码 / 环境变量中，前端永远拿不到
  • 前端只持有临时 JWT，过期后自动失效
  • 后端可附加业务逻辑：鉴权、限流、日志、会话隔离
  • RT 轮换时只改后端，前端无感知

3.3 后端内部流程（推演）

后端 /bot/token.xt 的实现代码不在本项目前端目录中（部署在服务器），基于 Coze OAuth 标准流程推演如下：

// 伪代码 — 后端 /system/bot/token.xt

// 1. 读取 RT（Coze OAuth 应用的密钥，存储在后端环境变量或配置文件中）
$rt = getenv('COZE_APP_SECRET');     // 或从配置文件读取
$appId = getenv('COZE_APP_ID');

// 2. 调用 Coze OAuth API 签发 access_token
$ch = curl_init('https://api.coze.cn/v1/oauth/token');
curl_setopt_array($ch, [
  CURLOPT_POST => true,
  CURLOPT_RETURNTRANSFER => true,
  CURLOPT_HTTPHEADER => ['Content-Type: application/json'],
  CURLOPT_POSTFIELDS => json_encode([
    'grant_type' => 'client_credentials',  // 客户端凭证模式
    'client_id' => $appId,
    'client_secret' => $rt,                // RT 作为密钥
  ]),
]);
$resp = json_decode(curl_exec($ch), true);

// 3. 判断结果
if (isset($resp['access_token'])) {
  echo json_encode(['ok' => 1, 'accessToken' => $resp['access_token']]);
} else {
  echo json_encode(['ok' => 0, 'msg' => 'Coze 授权失败: ' . ($resp['error_description'] ?? 'unknown')]);
}
📘 RT 的角色

RT 是 Coze OAuth 应用创建时获得的应用密钥（App Secret）。后端用它 + App ID 向 Coze 请求 client_credentials 类型的 access_token。Coze 验证 RT 有效后，签发一个有时效的 JWT 返回给后端，后端再透传给前端。

RT 只存在后端，前端代码、IndexedDB、Network 请求中均不出现 RT。

4.1 全局变量

4.2 fetchCozeToken() — 向后端请求 JWT

（[index.html 1786-1797 行](file:///Users/guorui/同步空间/20021218/临时开发/智能制单/拼音试验/dexiedb/index.html#L1786-L1797)）

async function fetchCozeToken() {
  try {
    var response = await fetch(API_BASE + '/bot/token.xt');
    if (!response.ok) throw new Error('令牌接口返回错误: ' + response.status);
    var data = await response.json();
    if (data.ok !== 1 || !data.accessToken) throw new Error(data.msg || '获取令牌失败');
    return data.accessToken;
  } catch (e) {
    console.error('fetchCozeToken error:', e);
    throw e;
  }
}
步骤代码说明
1 fetch(API_BASE + '/bot/token.xt') GET 请求后端令牌接口
2 response.ok 检查 HTTP 状态码 200-299
3 data.ok !== 1 检查业务层成功标记
4 !data.accessToken 检查 token 非空
5 return data.accessToken 返回 JWT 字符串

4.3 initCozeSDK() — OAuth 模式的初始化

当 agent.token 为空时，走 OAuth 分支（[index.html 1799-1869 行](file:///Users/guorui/同步空间/20021218/临时开发/智能制单/拼音试验/dexiedb/index.html#L1799-L1869)）：

async function initCozeSDK() {
  document.getElementById('apiStatus').textContent = '正在获取授权...';

  try {
    // ① 读取 Agent 配置
    var agent = await loadActiveAgent();
    var useBotId = (agent && agent.bot_id) ? agent.bot_id : '7638933573109792777';

    // ② OAuth 模式：agent.token 为空 → 走后端签发
    var useToken = (agent && agent.token) ? agent.token : await fetchCozeToken();
    cozeAccessToken = useToken;

    // ③ 检查 SDK 是否加载
    if (typeof CozeWebSDK === 'undefined') {
      throw new Error('Coze SDK 未加载，请刷新页面');
    }

    // ④ 销毁旧实例
    if (cozeClient && typeof cozeClient.destroy === 'function') {
      cozeClient.destroy();
    }

    // ⑤ 创建新实例
    cozeClient = new CozeWebSDK.WebChatClient({
      config: {
        bot_id: useBotId,
      },
      auth: {
        type: 'token',
        token: useToken,           // OAuth 签发的 JWT
        onRefreshToken: async function () {
          // ⑥ JWT 过期时自动续期
          try {
            if (agent && agent.token) return agent.token;  // PAT 模式不续期
            cozeAccessToken = await fetchCozeToken();          // OAuth 重新签发
            return cozeAccessToken;
          } catch (e) {
            console.error('onRefreshToken error:', e);
            return cozeAccessToken;  // 降级：返回旧 token 保活
          }
        }
      },
      ui: {
        base: { lang: 'zh-CN', zIndex: 50 },
        asstBtn: { isNeed: true },
        chatBot: {
          title: (agent && agent.name) ? agent.name : '智能制单助手',
          uploadable: true,
          width: 460,
        },
        header: { isShow: true, isNeedClose: false }
      }
    });

    // ⑦ 弹出聊天窗口
    setTimeout(function() {
      if (cozeClient && typeof cozeClient.showChatBot === 'function') {
        cozeClient.showChatBot();
      }
    }, 500);

    document.getElementById('apiStatus').textContent = '已连接 ✅';
    document.getElementById('apiStatus').style.color = '#16a34a';

  } catch (e) {
    console.error('Coze SDK 初始化失败:', e);
    document.getElementById('apiStatus').textContent = '启动失败: ' + e.message;
    document.getElementById('apiStatus').style.color = '#e5484d';
    showToast('智能体启动失败: ' + e.message);
  }
}

4.4 关键代码段对照

序号代码段OAuth 模式中的作用
① loadActiveAgent() 从 IndexedDB 读取 Agent 配置，判断 token 字段是否为空
② await fetchCozeToken() OAuth 核心：向后端请求 JWT
⑤ auth.token: useToken 将 JWT 注入 SDK 鉴权配置
⑥ onRefreshToken OAuth 核心：JWT 过期时自动重新签发

五、JWT 自动续期机制

5.1 续期流程

SDK 检测 JWT 过期
→
调用 onRefreshToken()
→
fetchCozeToken()
→
后端重新签发
→
返回新 JWT
→
SDK 自动替换

5.2 续期回调代码

onRefreshToken: async function () {
  try {
    // PAT 模式：token 不过期，直接返回原值
    if (agent && agent.token) return agent.token;

    // OAuth 模式：重新请求后端签发
    cozeAccessToken = await fetchCozeToken();
    return cozeAccessToken;
  } catch (e) {
    console.error('onRefreshToken error:', e);
    return cozeAccessToken;  // 降级：返回旧 token，尽量保活
  }
}

5.3 降级策略

⚠️ 续期失败时的降级

当 fetchCozeToken() 在续期时失败（网络抖动、后端重启等），回调返回旧的 cozeAccessToken而非抛错。

目的：避免因一次续期失败就中断用户对话。旧 token 虽然已过期，但 SDK 内部会重试，用户感知不到短暂故障。

风险：如果后端长时间不可用，旧 token 最终也会被 Coze 拒绝，此时对话会报鉴权错误。

5.4 PAT vs OAuth 续期对比

维度PAT 模式OAuth 模式
token 有效期 长期有效（手动撤销才失效） 短期（通常 1-2 小时）
续期方式 不续期，直接返回原值 重新调用后端 /bot/token.xt
续期失败影响 不会失败 降级返回旧 token，可能最终断连
网络依赖 无（token 在本地） 依赖后端可达 + Coze API 可达

六、Coze OAuth 应用配置指南

6.1 在 Coze 平台创建 OAuth 应用

  1. 登录 Coze 开放平台
  2. 进入「扣子 API」→「OAuth 应用」
  3. 点击「创建应用」，选择应用访问令牌类型
  4. 填写应用名称和描述
  5. 创建后获得：
    • App ID（应用 ID）
    • App Secret（即 RT / 应用密钥）
  6. 在应用配置中关联目标 Bot（智能体）

6.2 后端配置

将 App ID 和 RT 配置到后端环境变量或配置文件中：

# 环境变量示例
COZE_APP_ID=xxxxxxxxxxxx
COZE_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx  # 即 RT
🔴 安全红线
  • RT 绝对不能出现在前端代码、HTML、JS、配置文件中
  • RT 绝对不能提交到 Git 仓库（加入 .gitignore）
  • RT 绝对不能出现在 F12 Network 请求参数中
  • 后端日志中不要打印 RT 的完整值
  • 定期在 Coze 平台轮换 RT（重新生成 App Secret）

6.3 前端配置（启用 OAuth 模式）

在智能体配置界面中，将 Token 字段留空即可启用 OAuth 模式：

字段PAT 模式OAuth 模式
Bot ID 填写 填写
Token 填写 PAT 令牌 留空
Name 填写（可选） 填写（可选）
✅ 一键切换

清空 Token 字段 → 保存 → 自动切换到 OAuth 模式。填入 Token 字段 → 保存 → 自动切换到 PAT 模式。无需改代码。

七、安全分析

安全维度OAuth 模式状态说明
RT（密钥） 后端隔离 前端代码、IndexedDB、Network 中均不出现 RT
access_token（JWT） 临时持有 存于内存变量 cozeAccessToken，有过期时间
Bot ID 前端可见 写在 JS 中，F12 可见，但 Bot ID 本身不是密钥
会话隔离 未启用 fetchCozeToken() 未传 session_name，所有用户共享同一 token
HTTPS 传输 建议启用 JWT 在传输过程中应使用 HTTPS 加密
Token 轮换 自动 SDK 检测过期后自动调用 onRefreshToken

八、故障排查

Q1：启动时提示"获取令牌失败"

  1. 检查后端 /system/bot/token.xt 是否可访问（直接在浏览器访问该 URL）
  2. 检查后端环境变量 COZE_APP_ID 和 COZE_APP_SECRET 是否配置正确
  3. 检查 RT 是否过期（在 Coze 平台确认 OAuth 应用状态）
  4. 查看后端日志，确认 Coze API 返回的错误信息

Q2：对话中途突然断连

  1. 打开 F12 → Console，搜索 onRefreshToken error
  2. 如果存在该日志，说明 JWT 续期失败（后端不可达或 Coze API 异常）
  3. 等待几秒后 SDK 会自动重试，或手动点击"启动智能体"重新初始化

Q3：F12 Network 中看到 /bot/token.xt 的响应

这是正常的。响应中的 accessToken 是临时 JWT，不是 RT。JWT 有过期时间，即使被截获，有效期也很短。

Q4：如何确认当前使用的是 OAuth 模式而非 PAT 模式

  1. 打开 F12 → Console
  2. 在智能体配置中查看 Token 字段是否为空
  3. Token 为空 → OAuth 模式；Token 有值 → PAT 模式
  4. 或检查 Network 中是否有 /bot/token.xt 请求（OAuth 模式独有）

九、与 PAT 模式的完整对比

维度PAT 模式OAuth 模式（本文档）
密钥位置 前端 IndexedDB 后端环境变量
密钥类型 PAT（Personal Access Token） RT（App Secret / OAuth 应用密钥）
前端获取 token 方式 直接读取 agent.token 调用后端 /bot/token.xt
token 有效期 长期（手动撤销才失效） 短期（1-2 小时，自动续期）
续期机制 不需要续期 SDK 自动调用 onRefreshToken
网络依赖 无 依赖后端 + Coze API
F12 暴露面 PAT 完全可见 仅临时 JWT 可见
多用户隔离 无（共享 PAT） 可扩展（后端可按用户签发不同 session）
适用场景 开发调试 / 单人使用 生产环境 / 多用户
配置方式 Agent 配置中填 Token Agent 配置中 Token 留空
