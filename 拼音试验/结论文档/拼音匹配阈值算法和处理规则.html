1. 算法概述

拼音匹配算法将ASR语音识别结果（或用户输入文本）与后台数据库中的客户/产品记录进行模糊匹配。核心思路是：将中文文本转为拼音，在拼音空间中计算多维度相似度，加权汇总后按阈值分级处理。

算法由三个层次组成：

第一层：拼音生成 — 中英混合文本分段处理，中文段转拼音，非中文段保留原字符
第二层：四维评分 — 从4个独立维度计算相似度，加权汇总为最终得分
第三层：阈值分级 — 按得分和候选数量决定匹配状态（自动确认/候选/模糊/不匹配）
三种匹配模式（2026-05-24新增）
产品匹配现已拆分为三种独立可选模式，用户可在产品选择界面实时切换：
— 分词模式 (keyword)：仅使用中文分词关键词匹配，默认模式，适合参数描述型输入
— 拼音模式 (pinyin)：仅使用拼音四维评分，适合精确品名匹配和同音字纠错
— 混合模式 (mixed)：拼音+关键词双路融合（拼音55%+关键词45%），兼顾全面性
调度函数 fuzzyMatchProducts 根据全局变量 _matchMode 分发到对应匹配函数。详见《分词关键词匹配算法》第3章。
2. 拼音生成规则

输入文本可能是中英混合（如"排线 PM1200 20米"），需要分段处理：

字符类型 处理方式 示例 全拼输出 首字母输出
中文 pinyin-pro转拼音 排线 pai_xian px
英文/数字/符号 原样保留，空格转下划线 PM1200 pm1200 pm1200
混合 按段分别处理后拼接 排线 PM1200 20米 pai_xian_pm1200_20_mi pxpm120020m
关键设计：全拼中各段用 _ 分隔，便于后续词袋模型按 _ 分词。首字母拼接不分隔，用于快速首字母匹配。
3. 四维评分模型
拼音相似度 × 35% + 首字母匹配 × 25% + 词袋余弦 × 30% + 长度匹配 × 10% = 最终得分
维度1：拼音相似度
35%
计算ASR全拼与记录全拼的字符串相似度。底层由两个子指标取平均：
编辑距离得分：1 - levenshteinDistance(a, b) / maxLen，衡量插入/删除/替换的代价
LCS得分：2 × lcsLength / (a.length + b.length)，衡量最长公共子序列占比
最终：calcStringSimilarity = (编辑距离得分 + LCS得分) / 2
性能优化：为避免长产品名（含详细描述，拼音200+字符）导致 levenshteinDistance 计算量爆炸，评分前对拼音字符串做截断——全拼截断120字符（约覆盖前30个汉字），首字母截断60字符。核心区分信息（品类+型号+品牌）几乎都在前30字内，截断不影响匹配准确度，但计算量减少64%。
维度2：首字母匹配
25%
计算ASR首字母缩写与记录首字母缩写的字符串相似度。算法同维度1（编辑距离+LCS取平均）。
首字母生成规则：中文段用pinyin-pro的 pattern:'first' 取首字母；拼音格式的非中文段按 _ 拆分后取每个音节首字母。
示例：fei_er_gong_mao → 首字母 fegm（按音节取首字母，而非整体去空格）
维度3：词袋余弦相似度
30%
按 _ 分词后做余弦相似度计算，解决词序不同导致的匹配失败。
算法步骤：
1. 将全拼按 _ 分词，统计词频向量
2. 计算两个向量的余弦相似度：dotProduct / (‖A‖ × ‖B‖)
示例：gong_kong_yan_neng_zhu_ban vs zhu_ban_si_he_gong_kong_yan_neng，虽然词序不同，但词袋相同，余弦相似度=1.0
维度4：长度匹配
10%
衡量ASR拼音与记录拼音的长度差异：1 - |lenA - lenB| / max(lenA, lenB)
长度差异越大，得分越低。防止短查询误匹配长记录。
特殊路径：精确匹配加速
如果记录的原始名称（name字段）与输入完全相同，直接返回满分：pinyin=1, abbr=1, wordBag=1, length=1
如果记录名称包含输入文本，返回近满分：pinyin=0.95, abbr=0.9, wordBag=1, length=0.9
关于业务权重：原设计包含第5维"业务权重"（15%），但实际使用中从未赋值（始终为0），相当于浪费了15%的权重空间。已于2026-05-17移除，权重重新分配给前4个维度。详细判断条件见《自动确认和人工确认的判断条件》。
4. 阈值分级策略

四维加权得分计算完成后，根据得分和候选数量进行分级处理。产品和客户采用相同的分级逻辑：

≥90%
自动确认
精确匹配 · 自动确认
匹配得分≥90%，视为精确匹配，自动确认，状态标记为 confirmed，UI显示绿色边框。
产品匹配额外逻辑：如果同名产品有多条，依次尝试型号精确匹配→型号部分匹配→规格匹配；如果都无法区分，返回pending需人工选择；如果同名只有一条，直接确认。
≥80%
自动确认
唯一候选 · 自动确认
匹配得分≥80% 且只有一个匹配结果，自动确认，状态标记为 confirmed，UI显示绿色边框。
设计理由：只有一个候选且得分较高时，用户确认的概率极高，自动确认可减少操作步骤。
70-90%
候选推荐
高置信候选 · 待确认
匹配得分在70%-90%之间，有匹配结果但置信度不够高，状态标记为 pending，UI显示黄色边框。
用户可点击产品/客户卡片，在候选列表中选择或搜索其他选项。
45-70%
模糊提示
低置信匹配 · 待确认
匹配得分在45%-70%之间，匹配结果置信度较低，但仍有参考价值，状态标记为 pending，UI显示黄色边框。
包括两种情况：
— 只有1个匹配结果，得分45-70%
— 有多个匹配结果，最高得分45-70%
<45%
不匹配
低于阈值 · 不匹配
匹配得分低于45%（最低阈值），视为不匹配，不返回任何结果，状态标记为 error，UI显示红色边框。
用户可通过搜索弹窗手动查找，或新建产品/客户。

查询输入一致性：产品匹配时，查询端将品名+型号合并为 combinedName 传入 pinyinMatch，与数据库端拼音生成方式（品名+型号+规格合并生成拼音）保持一致，确保拼音空间对齐。
占位符过滤（isPlaceholder）：合并生成拼音时，空值、"-"、"[未填写]"、"[空]" 等方括号占位符不参与合并。例如：model="[未填写]" 表示型号为空，不应生成拼音，否则无意义的占位文本会严重干扰匹配得分（曾导致100%匹配降至55%）。过滤逻辑统一使用 isPlaceholder() 函数：.filter(s => !isPlaceholder(s))，判断规则：!val || val.trim() === '-' || val.trim() === '[未填写]' || /^\[.*\]$/.test(val.trim())

产品匹配阈值判断：

if (best.score >= 0.9) {
  var sameNameProducts = products.filter(p => p.name === best.name);
  if (sameNameProducts.length > 1) {
    // 优先级1：型号精确匹配
    var modelMatch = sameNameProducts.find(p =>
      p.model.toLowerCase() === modelValue.toLowerCase());
    if (modelMatch)
      return { matchId: modelMatch.id, status: 'confirmed', matchType: 'sku' };
    // 优先级2：型号部分匹配（双向包含）
    var modelPartial = sameNameProducts.find(p =>
      p.model.indexOf(modelValue) !== -1 || modelValue.indexOf(p.model) !== -1);
    if (modelPartial)
      return { matchId: modelPartial.id, status: 'confirmed', matchType: 'sku' };
    // 优先级3：规格匹配
    var specMatch = sameNameProducts.find(p =>
      p.spec.indexOf(specValue) !== -1);
    if (specMatch)
      return { matchId: specMatch.id, status: 'confirmed', matchType: 'sku' };
    // 无法区分：人工选择
    return { matchId: best.id, status: 'pending', matchType: 'name' };
  }
  // 同名唯一：自动确认
  return { matchId: best.id, status: 'confirmed', matchType: best.score >= 0.95 ? 'exact' : 'name' };
}
if (matches.length === 1 && best.score >= 0.8) {
  // 唯一候选且≥80%：自动确认
  return { matchId: best.id, status: 'confirmed', matchType: 'name' };
}
if (best.score >= 0.7) {
  // 高置信候选：待确认
  return { matchId: best.id, status: 'pending', matchType: 'name' };
}
if (matches.length === 1 && best.score >= 0.4) {
  // 唯一低置信候选：待确认
  return { matchId: best.id, status: 'pending', matchType: 'name' };
}
if (matches.length > 1 && best.score >= 0.4) {
  // 多个低置信候选：待确认
  return { matchId: best.id, status: 'pending', matchType: 'name' };
}
// 低于阈值：不匹配
return { matchId: null, status: 'error', matchType: 'none' };

8. 阈值策略总结
得分范围 候选数 状态 UI颜色 用户操作
≥90% 任意 confirmed 🟢 绿色 无需操作，自动确认
≥80% 仅1个 confirmed 🟢 绿色 无需操作，自动确认
70-90% 任意 pending 🟡 黄色 点击确认/选择其他候选
45-70% 任意 pending 🟡 黄色 点击确认/搜索/新建
<45% — error 🔴 红色 搜索其他/新建
核心设计原则
高置信自动确认：得分≥90%或唯一候选≥80%时自动确认，减少用户操作步骤
低置信人工介入：得分70-90%需要用户确认，70%以下需要用户主动选择
不匹配提供出路：得分低于45%时提供搜索和新建功能，确保用户始终有操作路径
阈值调优建议
当前最低阈值0.45（45%）是基于实际业务数据调优的结果。如果出现误匹配过多，可上调至0.5；如果漏匹配过多，可下调至0.4。建议在调整阈值前，先用 get_cus_pro.html 工具页的测试功能验证效果。
