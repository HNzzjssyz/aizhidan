# 冷启动拼音数据进度提示优化方案

> 状态：待评审
> 范围：`dev/index.html` + `prod/index.html`（通过 `_build_split.py` 生成）
> 不涉及：`pinyin_sync.js` / `pinyin_match.js`（进度数据已就绪，无需改动）

---

## 一、问题与目标

### 1.1 用户感知问题

首次冷启动（本地无拼音数据或数据陈旧）时，用户在顶部"拼音数据"面板只看到静态的"未就绪"提示，2 秒后弹出一个 toast，随后漫长等待中**没有任何进度反馈**。用户不知道：
- 系统在干什么（是在准备数据还是卡住了）
- 要等多久
- 当前进行到哪一步

### 1.2 根因（代码事实）

同步模块 `pinyin_sync.js` **已实现细粒度 `onProgress` 回调**，但前端未接入：

| 代码位置 | 现状 |
|---------|------|
| [pinyin_sync.js:262](dev/pinyin_sync.js#L262) `fetchFullPaged` | 已回调 `onProgress('读取客户数据...', current, total, '第N批')` 分片级进度 |
| [pinyin_sync.js:494](dev/pinyin_sync.js#L494) `fetchFullData` | 已回调客户/产品分片进度 |
| [pinyin_sync.js:420](dev/pinyin_sync.js#L420) 增量同步 | 已回调 `onProgress('增量同步中...', 1/2/3, 3, '客户合并...')` 三段式 |
| [index.html:5956](dev/index.html#L5956) `autoSyncIfNeeded` 调用 | **只接了 `onLog` / `onToast`，未接 `onProgress`** ← 断点 |

**结论**：进度数据已完备，缺的是前端接收与渲染。

### 1.3 目标

让用户在冷启动时明确感知"系统正在准备拼音数据"，并看到实时进度，降低等待焦虑。不改变现有同步逻辑与性能特征。

## 二、现状流程梳理

### 2.1 冷启动时序（[index.html:5936-5979](dev/index.html#L5936)）

```
PinyinMatch.init()
  → refreshPinyinStatus()           // 显示"未就绪"或"已就绪"
  → initCozeSDK()
  → PinyinSync.init() + onSyncComplete 监听
  → _autoSelectCustomerByUrl()      // cu_id 场景，走 API 不依赖本地
  → setTimeout(2000)
      → PinyinSync.autoSyncIfNeeded({
          hooks: { onLog, onToast }  // ← 缺 onProgress
        })
      → refreshPinyinStatus()       // 同步完成后刷新
      → showToast('数据已自动同步')
```

### 2.2 当前面板 UI（[index.html:1108-1118](dev/index.html#L1108)）

```
┌──────────────────────────────────────────────────────────┐
│ 🗄 拼音数据   [静态文字：未就绪 / 已就绪 · 统计]   [打开工具] │
└──────────────────────────────────────────────────────────┘
```

- 容器：`#pinyinDataPanel`（紫色边框卡片）
- 状态文字：`#pinyinDataStatus`（由 `refreshPinyinStatus()` 填充）
- 同步期间：面板内容**不变**，仅靠 toast 提示

### 2.3 进度回调签名（已有）

`onProgress(title, current, total, subtext)`

| 参数 | 含义 | 示例 |
|------|------|------|
| title | 阶段标题 | `'读取客户数据...'` |
| current | 当前进度 | `12000` |
| total | 总量 | `50000` |
| subtext | 子说明 | `'第 2 批'` |

## 三、方案设计

### 3.1 总体思路

1. **接入** `onProgress` 回调
2. **复用** 顶部 `#pinyinDataPanel` 区域渲染进度（不新建浮层，位置固定显眼）
3. **补全** 冷启动各阶段的文字提示（init → 同步中 → 完成）

### 3.2 阶段定义与提示文案

| 阶段 | 触发时机 | 面板显示文案 | 进度条 |
|------|---------|-------------|--------|
| 初始化 | `PinyinMatch.init()` 完成、同步未启动 | ⏳ 正在准备拼音数据... | 不定（脉冲动画） |
| 全量-客户 | `onProgress('读取客户数据...')` | 📥 读取客户数据 12000/50000 | 24% |
| 全量-产品 | `onProgress('读取产品数据...')` | 📥 读取产品数据 40000/50000 | 80% |
| 增量-合并 | `onProgress('增量同步中...', 1, 3)` | 🔧 客户合并... | 33% |
| 增量-产品 | `onProgress('增量同步中...', 2, 3)` | 🔧 产品合并... | 66% |
| 增量-拼音 | `onProgress('增量同步中...', 3, 3)` | 🔧 拼音生成... | 100% |
| 跳过 | 数据新鲜（<1h） | 直接走 `refreshPinyinStatus()` 已就绪 | 无 |
| 完成 | 同步结束 | ✅ 已就绪 · 客户 N 条 · 产品 N 条 | 消失 |

### 3.3 UI 效果示意

**冷启动瞬间**：
```
┌──────────────────────────────────────────────────────────┐
│ 🗄 拼音数据   ⏳ 正在准备拼音数据...                       │
└──────────────────────────────────────────────────────────┘
```

**全量同步中**：
```
┌──────────────────────────────────────────────────────────┐
│ 🗄 拼音数据   📥 读取客户数据  12000/50000  第 2 批        │
│             ████████░░░░░░░░░░░░░░░░░░░░░░  24%           │
└──────────────────────────────────────────────────────────┘
```

**阶段切换**：
```
📥 读取产品数据  40000/50000  ████████████████░░░░  80%
🔧 拼音生成     3/3           ██████████████████████ 100%
```

**完成**：
```
✅ 已就绪 · 客户 50000 条（拼音 50000）· 产品 50000 条 · 同步于 刚刚
```

## 四、改动点清单

仅改 `dev/index.html`（约 40 行），`prod/` 由 `_build_split.py` 自动生成。

### 4.1 新增渲染函数 `_renderSyncProgress(title, current, total, subtext)`

职责：在 `#pinyinDataStatus` 内渲染进度文字 + 进度条。
- 百分比：`Math.round(current / total * 100)`
- 进度条：`<div>` + 内嵌 `<div>` 宽度随百分比变化
- 面板左边框变为进行中色（如蓝色 `#3b82f6`），与"未就绪黄/已就绪绿"区分
- 极端值兜底：`total=0` 时显示不定脉冲条

### 4.2 新增阶段提示函数 `_showPinyinPreparing()`

职责：在 `PinyinMatch.init()` 后、`setTimeout` 触发同步前，立即显示"⏳ 正在准备拼音数据..."。
- 防止"init 完成 → 等 2 秒 → 同步启动"这段空窗期用户看到静态"未就绪"以为卡住
- 若 `hasPinyinData()` 为 true（本地已有数据），跳过此提示，直接走 `refreshPinyinStatus()`

### 4.3 接入 onProgress 回调

[index.html:5956](dev/index.html#L5956) 的 `autoSyncIfNeeded` hooks 增加：

```js
hooks: {
  onLog: function (msg) { console.log('[auto-sync]', msg); },
  onToast: function (msg, type) { showToast('自动同步：' + msg, type); },
  onProgress: function (title, current, total, subtext) {
    _renderSyncProgress(title, current, total, subtext);
  }
}
```

### 4.4 同步完成收尾

`autoSyncIfNeeded().then()` 内（已有 `refreshPinyinStatus()`），确保进度条被"已就绪"状态覆盖，无需额外清理（`refreshPinyinStatus` 重写 `#pinyinDataStatus` innerHTML 即清掉进度条）。

### 4.5 跨标签同步完成也复用

[index.html:5941](dev/index.html#L5941) 的 `PinyinSync.onSyncComplete` 回调已有 `refreshPinyinStatus()`，保持不变（跨标签同步是后台行为，本标签无需展示进度）。

## 六、待确认决策点

1. **进度展示位置**
   - [ ] A. 复用顶部 `#pinyinDataPanel`（推荐：位置固定、无需新增容器、与"已就绪"同位切换）
   - [ ] B. 新建顶部浮层 / 全屏遮罩（更醒目但侵入性强）
   - [ ] C. Toast 流式（轻量但转瞬即逝，不适合长进度）

2. **进度条样式**
   - [ ] A. 紧凑内嵌条（高 4-6px，与面板文字同行，推荐）
   - [ ] B. 醒目大条（独立一行，高 8-12px，占位多但远处可见）

3. **完成后过渡**
   - [ ] A. 立即切"已就绪"（干脆，推荐）
   - [ ] B. 停留 1 秒展示"✅ 完成"再切（仪式感，但拖沓）

4. **数据新鲜跳过同步时**
   - [ ] A. 不显示进度提示，直接"已就绪"（推荐，本就无需等待）
   - [ ] B. 短暂闪现"数据已最新"提示
